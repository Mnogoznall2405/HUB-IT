# Реестр релизов

Релиз — версия + неизменяемый SHA и артефакт, а не ветка/PR. Источник бинарной идентичности — manifest и SHA-256 из [штатного packaging](../scripts/releases/README.md). Для выпуска хранить одну запись с ссылками на release gate и runbook, не переписывая логи и списки коммитов.

| Поле | Последний проверенный кандидат из Git |
|---|---|
| Версия / исходники | Номер общей поставки и артефакт не назначены. `4d4dba1f` = дерево `d008cf60` из #75. Полный состав см. [#75](https://github.com/Mnogoznall2405/HUB-IT/pull/75), [состояние](PROJECT_STATUS.md) и [исторический RC](../documentation/technical/UNIFIED_RELEASE_CANDIDATE.md). |
| Схема | Цели по исходникам — в [реестре миграций](MIGRATION_REGISTRY.md). Последнее зафиксированное наблюдение в историческом runbook: production app/chat `20261124_0179` на 2026-11-25; не использовать как текущее. |
| Проверки и ограничения | [Историческая верификация](../documentation/technical/UNIFIED_RELEASE_VERIFICATION.md) содержит разные SHA и незелёные полные suites. [PRODUCTION_READINESS.md](../documentation/technical/PRODUCTION_READINESS.md) §11.1 сообщает о PG rehearsal цепочки до `0182`, §13 — о проверках на `667ec342` до последних коммитов RC. Ни то, ни другое не заменяет проверку неизменяемого RC и артефакта. |
| Порядок / rollback | Использовать утверждённый runbook и DBA checklist; подготовить старый артефакт, backup БД/файлов и проверенный restore, совместимость старого кода с новой схемой и план отката SW. Не предполагать, что downgrade всегда обратим и сохраняет данные. |
| Staging | Исторически описана проверка на изолированном PostgreSQL со схемой, подобной production; текущий live staging SHA/manifest и состав сервисов **не подтверждены**. |
| Production / разрешение | Версия приложения, ревизии БД и выкат #75 сейчас **не подтверждены**. Разрешения владельца на staging, merge #73 и production нет в этом срезе. Готовность выката не оценена (`NOT TESTED`). |

Для новой записи Release Manager фиксирует версию, SHA и SHA-256 артефакта, включённые PR и schema revisions, результаты gate по точному SHA и ограничения, порядок выкатки/rollback/restore, timestamps/подтверждения staging и production, ссылку на разрешение владельца. Успешный rehearsal не равен живому staging, merge не равен deploy. Пока состав будущего RC не выбран, не запускать отдельную консолидацию и не маркировать релиз готовым.
