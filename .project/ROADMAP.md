# Ближайшая дорожная карта

Без дат выката, новых функций и параллельных программ консолидации. Основание — [состояние](PROJECT_STATUS.md) и [аудит](PROCESS_AUDIT.md). Это направления, не карточки задач. Порядок: проверить уникальную дельту → зафиксировать состав RC и обеспечить воспроизводимые ворота → развивать только подтверждённые остатки.

| Направление | Следующий полезный шаг |
|---|---|
| Dashboard | Smoke карточек и ошибок refresh на выбранном RC; использовать существующие сценарии навигации, не начинать редизайн. |
| Мессенджер | В #73 проверить warm-dock, доставку/ACK и сохранность Sticker V2/recents. В offline journal не инвестировать без подтверждённого пользовательского риска. |
| Почта | Проверить draft/preview/read-state в интегрированном дереве на синтетическом почтовом контуре; Exchange оставить отдельным решением. |
| Мои файлы | Первым разобрать #73: массовые операции с частичным отказом, лимит upload, недоступные deep links, сессии редактора и сохранение V3.2. Не открывать новый perf-цикл. |
| Корпоративный ИИ | Сохранить A1–A10 и профиль флагов без расширения. #74 A11 — после синхронизации с main и независимого holdout по READ/ACT, ACL, качеству и стоимости; вне текущего релиза. |
| Адресная книга | В #73 проверить изменения выбора/поиска контакта и деградированный upstream; отдельная разработка только при доказанной регрессии. |
| Структура компании | Smoke просмотра структуры и связанных отсутствий после remediation, включая ограниченную роль и мобильную ширину. |
| Инвентаризация | Smoke поиска оборудования, QR deep-link, больших списков/розеток; сохранить раздельные Inventory/Scan и обособить серверные DLP-данные. |
| Специализированные модули | Smoke Tasks/Tickets, Monitoring, Scan Center, 1С/Docflow, Construction, Voice; фиксировать, какие внешние интеграции не seed-ированы, не считать shell полной проверкой. Для Tasks сверить #10 с #73. |
| Мобильное приложение | Related tests и целевой smoke Android на совместимость login/reconnect/уведомлений с текущим API, по риску релиза; без Capacitor. |
| Desktop | Стабильность WebView2/origin/update, Release smoke при затронутом контракте; сохранить текущие native screens, нативный чат заморожен до решения. |
| Инфраструктура | Пилот рекомендательного PR gate со статическим Alembic, изолированными профилями и одним интегратором. Затем staging и проверенный rollback для точного кандидата. |
| Безопасность | Проверить сохранность auth/sticker и безопасной вставки при merge. Любая политика регистрации устройства/релизных доступов — отдельное решение владельца. |
| Производительность | Повторять A/B только для затронутых сценариев относительно точного `main`. First response/UI feedback важнее ещё одного широкого цикла. |
