## 3. Независимая техническая проверка шести приоритетных находок

### FE-0059 — Обрыв сети >15 с при ротации refresh → разлогин (High, Confirmed)

- **Первопричина:** одноразовая ротация refresh-токена с grace-окном
  `refresh_rotation_grace_seconds` = 15 с и `_REFRESH_GRACE_MAX_HITS = 1`
  (`WEB-itinvent/backend/api/v1/auth.py:1648,135,1656–1687`). Обрыв/потеря ответа
  длиннее окна → старый токен «already used» → 401 → `invalidateSession`.
- **Влияние:** принудительный разлогин с потерей несохранённого ввода; характерно
  для мобильных сетей/Wi-Fi-роуминга/VPN-переключений. Задокументировано как
  компромисс (AUTH_SECURITY_STACK.md:18–19).
- **Воспроизводимость:** подтверждена живой эмуляцией офлайна на /chat
  (сессия ~50 мин, access-TTL 15 мин): auth/me 401 → auth/refresh 401 → logout.
- **Исправление (за владельцем):** grace 60–120 с для web-клиента ИЛИ мягкое
  восстановление (relogin-хинт с сохранением черновиков). Auth-политику не менять
  как side effect — только отдельным решением.
- **Регрессионные тесты:** backend-unit на refresh-роут («повтор в grace — успех;
  повтор после grace — 401 + family revoke»); e2e — «обрыв сети N с → сессия
  жива/восстановлена, черновики сохранены».

### FE-0022 — Warehouse1C: строки недоступны с клавиатуры (High, Confirmed)

- **Первопричина:** TableRow/TableCell с `onClick` без role/tabIndex/onKeyDown
  (`Warehouse1C.jsx:2163–2216, 1975–1980`); мобильный рядок (:487) сделан правильно —
  асимметрия.
- **Влияние:** пользователи клавиатуры/скринридеров не могут открыть карточку
  документа и сопоставление 1С↔HUB.
- **Воспроизводимость:** статическая (код); поведение подтверждается a11y-моделью
  (кликабельный элемент не фокусируется).
- **Исправление:** дублировать паттерн мобильного рядка (role="button", tabIndex,
  Enter/Space) или добавить явную кнопку «Открыть» в строку.
- **Регрессионные тесты:** Playwright — «Tab до строки → Enter → открылась карточка»;
  axe — отсутствие click-без-keyboard в таблицах Warehouse1C.

### FE-0023 — Мобильная вкладка «Оборудование» без виртуализации (High, Confirmed)

- **Первопричина:** isMobile-ветка рендерит `displayedPorts.map` карточками
  (`EquipmentTab.jsx:351–433`) без виртуализации, при лимите выборки 10 000
  (`Networks.jsx:871`; розетки — `:765`, `SocketsTab.jsx:220–229`); desktop
  виртуализируется (`rowHeights :203`, `slice(startIndex,endIndex) :218`).
- **Влияние:** на филиале с тысячами портов мобильная вкладка фризит/падает.
- **Воспроизводимость:** статическая (код + подтверждённый лимит).
- **Исправление:** react-window (уже в зависимостях) либо пагинация/«показать ещё»
  для мобильной раскладки.
- **Регрессионные тесты:** unit — рендер EquipmentTab isMobile с 10k элементов
  монтирует только окно (не 10k DOM-узлов); замер до/после на реальном филиале.

### FE-0004 — Экран входа на /shared-folders/:invalid (было High; теперь Medium/Suspected)

- **Первопричина (текущее понимание):** наблюдение 2026-11-22 17:16–17:18 (дважды) в
  Chrome владельца не воспроизводится: в чистом профиле — корректная ошибка
  «Папка недоступна…» (проверено и в точной последовательности исходного сценария:
  /dashboard → /nonexistent → /shared-folders/invalid, с return-path в sessionStorage).
  Деплой в окне наблюдения исключён (IIS-файлы не менялись с 20.11 15:10).
  Вероятная причина — устаревший service-worker app-shell в долгоживущем профиле
  (skipWaiting только по явному сообщению).
- **Влияние:** прямое — пользователь со старым shell видит устаревшие маршруты до
  перезагрузки (шире: любые новые маршруты после деплоев).
- **Воспроизводимость:** только в исходном профиле; в чистом — нет.
- **Исправление (если подтвердится):** UX обновления SW (подсказка «доступна новая
  версия» после деплоя) — согласовать политику.
- **Регрессионные тесты:** e2e «публичные ссылки без сессии»: `/shared-files/:invalid`
  и `/shared-folders/:invalid` → тексты ошибок, URL не меняется.

### FE-0056 — Удаление/перемещение черновика → API 400 (Medium, Confirmed по API)

- **Первопричина (вероятная):** черновик, сохранённый из композера, не находится
  при операции move/delete: `_message_item` → `resolve_folder`/`get` →
  «Message not found» (`mail_message_actions.py:83–94`) → MailServiceError → 400.
  Точная ветка требует воспроизведения с захватом тела 400 (needsBackendCheck).
- **Влияние:** сценарий «удалить только что сохранённый черновик» ломается;
  состояние самовосстанавливается синхронизацией (черновик исчез из папки после
  ресинка). Отображение ошибки в UI существует (setError → Alert) — видимость
  при неудаче требует live-проверки.
- **Воспроизводимость:** подтверждено сетью (POST delete → 400, POST move → 400).
- **Исправление:** backend — разобраться с резолвом черновиков (почему exchange_id
  не находится сразу после сохранения); фронт — убедиться, что Alert показывается.
- **Регрессионные тесты:** backend-e2e: save draft → delete draft → 200 (сейчас 400);
  фронт-e2e: удаление черновика показывает сообщение при неудачном ответе.

### FE-0064 — Self-XSS через paste в мобильном редакторе описания (Medium, Confirmed статически)

- **Первопричина:** единственный в кодовой базе contentEditable без перехвата paste
  (`MobileCreateDescriptionEditor.jsx:81–91`): начальное значение санируется (:30),
  чтение безопасно (:37), но вставленный из буфера HTML попадает в DOM origin
  до конвертации — атрибуты вида onerror исполняются в момент вставки.
  Контраст: почтовый редактор paste перехватывает и санирует
  (`MailRichTextEditor.jsx:161–192`, sanitizeComposePasteHtml → DOMPurify).
- **Влияние:** вектор — social engineering («вставьте этот текст в описание»);
  mobile-раскладка создания задачи. Данные при сохранении нейтрализуются —
  персистенции нет, исполнение разовое.
- **Воспроизводимость:** статическая; runtime-исполнение НЕ проверялось (политика:
  security-пробы только на тестовом окружении). План для стенда: paste
  `<img src=x onerror="…">` в редактор → проверить исполнение; после фикса —
  то же вставка должна давать только текст.
- **Исправление:** обработчик paste по образцу MailRichTextEditor либо вставка
  только `text/plain`.
- **Регрессионные тесты:** unit (jsdom) — вставка HTML через ClipboardEvent в
  редактор не оставляет опасных узлов; e2e на стенде.
