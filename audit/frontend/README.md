# Аудит web-фронтенда HUB-IT (WEB-itinvent/frontend)

Непрерывный глубокий аудит веб-версии. Цель — найти реальные, воспроизводимые
дефекты фронтенда и подтвердить их доказательствами. Исправление дефектов
выполняется отдельными задачами с разрешения владельца — этот аудит не меняет
код приложения.

## Объект аудита

- Код: `WEB-itinvent/frontend/src` (React 18, Vite 7, MUI 5, react-router-dom 7)
- Маршруты: `WEB-itinvent/frontend/src/App.jsx`
- Тесты: vitest (`unit-node`, `ui-dom`), Playwright `e2e/`
- Production frontend: IIS (`C:\inetpub\wwwroot\itinvent`, https://hubit.zsgp.ru/)

## Структура

| Файл | Назначение |
|---|---|
| `AUDIT_PROGRESS.md` | Отчёт по циклам аудита, точка продолжения |
| `ISSUES.md` | Карточки дефектов (человекочитаемые) |
| `ISSUES.json` | Машиночитаемый реестр дефектов |
| `COVERAGE_MATRIX.md` | Матрица покрытия маршрутов/страниц |
| `PERFORMANCE.md` | Замеры и находки производительности |
| `UX_UI.md` | UX/UI находки и предложения (не дефекты — отдельно) |
| `ARCHITECTURE.md` | Архитектурная карта и находки |
| `TEST_RESULTS.md` | Результаты запусков тестов/линтеров/сборки |
| `NEXT_ACTIONS.md` | Очередь следующих шагов |
| `evidence/` | Скриншоты, логи, трейсы, профили |

## Правила

1. Один дефект — одна запись (ID `FE-NNNN`); повторное обнаружение дополняет карточку.
2. Статус `Confirmed` — только с фактическими доказательствами; иначе `Suspected`.
3. Пути к файлам и номера строк — только реально проверенные.
4. Без секретов, токенов, персональных данных и конфиденциальных ответов API.
5. Production (backend :8001/:8002/:8011 на этом сервере, IIS) — только read-only:
   никаких мутаций, рестартов, сборок в `dist/`.
6. Мутационные сценарии (создание/редактирование/удаление) выполняются только
   в изолированном окружении; при его отсутствии — статус `BLOCKED` с причиной.
