# OUTLOOK_STYLE_REDESIGN.md — переработка нативной почты по образцу Outlook

Живой журнал этапов задачи «нативная почта → классический Outlook»
(`desktop/Hub.Desktop/Native`, C# / WPF / XAML). Верификация — как в
`WPF_MAIL_UI_AUDIT.md`: `dotnet test desktop/Hub.Desktop.sln -c Debug --filter
"FullyQualifiedName~NativeMailViewModelTests|FullyQualifiedName~NativeScreenshots"`
(STA-харнесс рендерит реальное `HubWindow` в PNG обеих тем + пиксельные проверки).

## Этап 1 — компоновка и размеры (готово)

- Grid: Row0 — командная панель, Row1 — контент, Row2 — статус-бар (структура уже была);
  колонки контента: **папки 220 DIP** (MinWidth 200, сплиттер), **список 380 DIP**
  (MinWidth 300, сплиттер), **чтение — всё остальное**.
- Сворачиваемое **главное меню** (гамбургер E700 в титлбаре `HubWindow`,
  `SetNavigationPaneCollapsed`): 216 DIP отдаются контенту.
- Сворачиваемая **рейка папок** (кнопка в её шапке → колонка 30 DIP с рычагом
  разворота): письмо получает ещё ~200 DIP. Вместе — на окне 1281 ширина чтения
  растёт с ~388 до ~675+ DIP.
- `GridSplitter` между всеми панелями; поведение на узких окнах — MinWidth колонок.

## Этап 2 — список писем: группировка и плотность (готово)

- **Группировка по датам Outlook**: `DateGroup` у строки («0|Сегодня», «1|Вчера»,
  «2|Ранее на этой неделе», «3|Ранее в этом месяце», «4|Ранее»; числовой префикс
  задаёт хронологический порядок групп при строковой сортировке WPF,
  `MailGroupHeaderConverter` отрезает его в заголовке). Подключение — дефолтный
  `CollectionView` коллекции Items в code-behind (`EnableMessageDateGrouping`).
- Компактность: карточка padding 8,5 → **8,4**, межкарточный отступ 3,2 → **3,1**
  (минус ~2 DIP на письмо = +2 видимых строки на экран).
- Строка письма: отправитель, дата справа, тема, превью, скрепка, ★, чекбокс,
  kebab/правый клик (было готово из итераций 2–7 журнала аудита).
- Состояния: непрочитано — bold + raised-фон + зелёная точка; hover — тон;
  выбрано — акцентный тинт + рамка (приоритет триггеров исключает конфликты).

## Этап 3 — панель чтения (готово)

- Шапка Outlook: аватар-инициалы, имя + адрес, «Кому/Копия», дата справа, тема,
  компактные действия + «Ещё ▾» (заголовки, .eml) — готово из итераций 8–10.
- **HTML-письма: белый «лист» всегда** (Outlook-поведение): раньше тёмная
  подложка + собственные `color:black` писем делали текст невидимым — исправлено
  (`DefaultBackgroundColor=White`, `Wrap(..., isDark: false)`).
- Ширина: потолок 760 → **1100** с растяжением по панели (максимальное
  использование ширины по заданию; на сверхшироких окнах потолок держит читаемость).
- Внутренних лишних скроллов нет: один DetailScrollViewer; WebView2 растягивается
  на высоту вьюпорта.

## Этап 4 — командная панель (готово)

Однорядная панель Outlook-Ribbon-стиля (~46 DIP) с логическими группами и
тонкими разделителями, каждая кнопка — существующая команда VM (недоступные
гасятся CanExecute):

- **Создание**: ✉ Новое письмо (primary), IT-заявка.
- **Сообщения**: ↩ Ответить, ↩↩ Ответить всем, ↪ Переслать, 🗑 Удалить,
  📁 Переместить ▾ (меню папок-целей).
- **Организация**: Прочитано/непрочитано, ❗ Важное, ＋ Папка.
- **Инструменты**: поиск (Ctrl+F/Esc из итераций 2/10) + ⟳ Обновить.

Поиск и кнопки больше не дублируют контекст папки (счётчик и «☑ Все» — в
заголовке списка, итерация 10). «Настройки» не добавлены — поддержки в нативной
почте нет (честнее, чем мёртвая кнопка).

## Этап 5 — папки и аккаунты (готово ранее + этот проход)

занимает место), счётчики: непрочитанные — серый gray-50, всего — мягкий бейдж,
избранное ★, контекстное меню (создать/переименовать/удалить по can_*),
drag&drop писем с подсветкой цели. Компактные строки 26 DIP, виртуализация.

## Этап 6 — светлая и тёмная темы (готово ранее)

Вся панель — DynamicResource палитр `HubColorsDark/Light` (светлая в духе Outlook:
белый фон, мягкие серые разделители, сдержанное синее выделение `#D7EBFA`-тинт);
текст никогда не задаётся локальным цветом. Тело письма — всегда белый лист
(см. Этап 3), контраст текста шапки/списка проверен WCAG-замерами (5.5–16.2:1,
журнал аудита, итерация 3).

## Оставшиеся отличия от эталона

1. Ribbon-вкладок (Файл/Главная/Отправить-получить) нет — однорядная панель
   (осознанное решение: вкладки съедают высоту, а вся логика помещается в ряд).
2. Сортировка списка по столбцам (Outlook-клик по заголовку) — не реализована:
   сервер отдаёт фиксированный порядок; нужен параметр sort в API.
3. Настройки вида (плотность/панели) — нативной поддержки нет.
4. DPI 125–200% и максимизированное окно — требуется живая проверка на экране
   пользователя (`bin\mail-preview\HUB.Desktop.exe --native`).

## Этап 8 — правки по живому скриншоту пользователя (готово)

Итерация после реального кадра (`live-mail.png`, ящик 854 письма):

- **Наложение «Важно» на тему** — пилюли важности/черновика были в той же

  колонку 2 (MailView.xaml ~1050). Тема читается целиком.
- **Поиск — один компонент**: иконка-лупа внутри поля (отступ 30 DIP),
  скоуп-чип «Все папки» примыкает справа (это именно область поиска —
  `FolderScope=all`, проверено по `BuildQuery`), тултип с горячими клавишами.
- **«Выбрать все» — чекбокс, не кнопка**: трёхсостояний
  `IsAllLoadedChecked` в VM (все/часть/ничего), indeterminate-глиф «−»
  добавлен в шаблон `HubCheckBoxStyle` (единственный потребитель стиля —
  почта). Подпись и тултип честно говорят «все загруженные»: выбор всех
  писем папки API не поддерживает (bulk идёт по конкретным id).
- **Карточки**: тема получила всю ширину строки — скрепка/★/kebab переехали
  в строку превью (правый край). Раньше действия съедали ~70 DIP темы.
- **Счётчики разведены**: заголовок — «854 писем · загружено 50»
  (`ListHeaderCountText`), кнопка — «Показать ещё (804)» с тултипом
  «Загружено 50 из 854» (`LoadMoreToolTip`, `RemainingCount`). Побочно
  исправлен баг: текст кнопки не обновлялся, когда `HasMore` не менял
  значение — уведомления счётчиков теперь идут из `OnSelectionChanged`.
- **Персист панелей (HKCU `Software\HUB-IT\Desktop`)**: ширина рейки папок
  (`MailFolderPaneWidth`), ширина списка (`MailListPaneWidth`), свёртка
  (`MailFolderPaneCollapsed`) — чтение до первого кадра, запись на
  `DragCompleted` сплиттеров и кнопках свёртки. Компактный режим двигает
  панели без записи (`ApplyFolderRailVisual` отделён от предпочтения).
  Сплиттеры `Focusable="True"` — стрелки ресайзят с клавиатуры.
- **Пустая панель чтения**: блок «Быстрые действия» убран; остались иконка,
  «Выберите письмо», одна строка и кнопка «Подсказки и клавиши ▾» — справка
  переехала в контекстное меню.
- **HTML-тело**: снят биндинг `WebView2.Height → DetailScrollViewer.ViewportHeight`
  (вернулся при переписи XAML после аварии: давал webview высоту шапки вместо
  области тела; размер задаёт строка Grid — как задокументировано в аудите,
  итерация 12). Текстовый fallback теперь реальный: виден, когда html нет
  ИЛИ WebView2 недоступен (`UpdateMailBodyVisibility`, `PlainBodyViewer`) —
  раньше при HasBodyHtml без рантайма область была пустой.

**Живая проверка** (Release-превью `bin\mail-preview`, реальный ящик):
письма грузятся (854/50/804 — счётчики согласованы), HTML-письмо открывается,
WebView2 создаёт `Document` в дереве автоматизации — рендер есть.
Пустое поле тела на PrintWindow-кадре — артефакт захвата (DComp-контент
WebView2 в DC окна не попадает), не дефект; пиксельное «нет белого
прямоугольника» подтверждается глазами на экране пользователя.

Проверки: сборка Debug+Release 0/0, тесты 90/90, кадры обеих тем
перегенерированы (`07*.png`, `L07*.png`).

## Этап 11 — тулбар, баг «воскрешающегося» редактора папок

колонке; свёртка гасит контейнер одним свойством — биндинги детей не
трогаются. Проверено циклом: открытие → свёртка сохраняет состояние →
отмена закрывает; закрытый не воскресает.
