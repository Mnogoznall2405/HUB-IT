# Память HUB Ассистента

Память обычного HUB Ассистента (`backend/ai_chat/`), отдельно от OpenCode.
Используются существующие PostgreSQL, worker и `shared/llm/`. Новых сервисов,
библиотек, векторного расширения или отдельной модели не требуется.

## Что хранится и как используется

1. **Личные факты между диалогами.** `app.ai_user_memories` содержит действующий
   факт — дословный фрагмент сообщения пользователя. `ai_memory_facts` задаёт
   устойчивый смысловой ключ и версию. Исправление обновляет один факт, а не
   добавляет противоречащую запись. `ai_user_memory_sources` связывает его с
   исходным сообщением. Предыдущая и новая версии записываются в `ai_memory_events`.
2. **Рабочая сводка диалога.** `ai_bot_conversations.rolling_summary` сохраняет
   цель, ограничения, принятые решения и незаконченные вопросы. При включённой
   памяти модель сжимает старые сообщения по смыслу. Последние 20 сообщений
   остаются в контексте непосредственно. Исправлена потеря середины диалога:
   граница сводки определяется этими 20 сообщениями, а не окном чтения из БД.
3. **Фактическое состояние действий.** Черновики и их статусы читаются из
   `ai_pending_actions` с проверкой пользователя и диалога. Просроченный pending
   показывается как expired без изменения БД. Сводка и личные факты не являются
   подтверждением отправки, разрешением или результатом инструмента.

После HTTP ACK worker одним запросом к текущей модели выбирает релевантные факты
по смыслу и предлагает remember/update/forget. Сервер проверяет существующие ID,
владельца, устойчивый ключ и дословную цитату из текущего сообщения. Из файлов,
секретов и утверждений о выполненных действиях личные факты не записываются.
Модель получает только память текущего пользователя. Вызов модели происходит
за пределами транзакции. Его токены включаются в usage основного запуска.

Это смысловой отбор моделью, а не поиск по embeddings. Кандидаты ограничены
200 последними активными фактами, контекст — 20 фактами / 4000 оценочных токенов
(рекомендуемое моделью число — до 6). Для больших архивов потребуется отдельная
оценка полноты поиска; первая версия не заявляет поиск по неограниченному архиву.
При сбое модели доступны только совпадающие по словам факты, статус записи —
unavailable. Ассистент не должен говорить «запомнил» без подтверждённого изменения.

## Конкурентность и управление

`ai_memory_state.revision` сериализует короткие записи по пользователю.
Запоздалая модель не может перезаписать более новую коррекцию или удаление.
Уникальный маркер `(user_id, message_id)` исключает повторное применение одного
сообщения. Ручные изменения устанавливают временную границу: старый ещё не
обработанный запрос не может восстановить забытый факт при повторном запуске.

Существующие HTTP операции и окно управления памятью сохраняются:

- `GET /api/v1/chat/ai/memory` — действующие факты, версии и ссылки-ID на источники;
- `PATCH /ai/memory/{id}` — ручное исправление;
- `DELETE /ai/memory/{id}` — удаление факта, источников и его снимков прошлых версий;
- `DELETE /ai/memory` — удаление всех фактов и снимков владельца;
- `PATCH /ai/memory/settings` — использование памяти пользователем.

При удалении сохраняются только пустые маркеры обработки, чтобы повторный запуск
не вернул старые факты. История самих чатов остаётся, как и раньше.
Очистка действует и при выключенном глобальном флаге.

Сводка обрабатывает до 200 старых сообщений за проход. При ошибке checkpoint не
продвигается: сообщения будут обработаны повторно. Запись сводки сравнивает прежние
checkpoint и reset marker; сброс контекста во время обработки отменяет старую подготовку.

## Источники проектных решений

- [Mem0, реализация памяти](https://github.com/mem0ai/mem0/blob/main/mem0/memory/main.py):
  смысловой поиск, ограничение кандидатов, фильтрация по пользователю и сверка новых
  сведений с найденной памятью. Текущий OSS add-путь использует additive extraction;
  поддержку UPDATE/DELETE в HUB реализуем самостоятельно, без приписывания её этому пути.
- [Graphiti, разрешение фактов](https://github.com/getzep/graphiti/blob/main/graphiti_core/utils/maintenance/edge_operations.py):
  источники эпизодов, объединение дублей и прекращение действия противоречащих фактов.
  Графовую инфраструктуру Graphiti в HUB не переносим.
- [Anthropic, управление контекстом](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents):
  компактные рабочие записи и сводки для продолжения длительных задач.

Код этих проектов не копировался; применены подходящие принципы к существующим
хранилищу, контрактам и проверкам HUB.

## Включение и откат

Глобальный `AI_PERSONAL_MEMORY_ENABLED` по умолчанию 0. Дополнительно действуют
флаги бота, диалога и пользователя; sandbox исключён. Без глобального включения
планировщик памяти не вызывается, прежняя свёртка контекста остаётся доступна.

Production включается отдельным согласованным релизом:

1. Read-only preflight: подтвердить целевую БД, текущую ревизию `20261005_0126`,
   схему `app`, отсутствие конфликтующих таблиц и активных AI-запусков; сохранить
   прежнее значение флага и снимок процессов. Не выводить строку подключения.
2. Через штатный Alembic применить **только `20261008_0127`** с явно заданным URL.
   Миграция добавляет три app-таблицы, существующие факты и chat-таблицы не изменяет.
3. В согласованном объёме установить `AI_PERSONAL_MEMORY_ENABLED=1` и загрузить
   код в AI worker и API-процессы. Для dual chat использовать
   `scripts/pm2/restart-chat-scale.ps1 -SkipSharedWorkers`; backend обновлять через
   `scripts/pm2/restart-backend.ps1 -SkipScanRestart`, чтобы ограничить релиз памятью.
   Без этого параметра backend-скрипт также рестартует Scan. Frontend-релиз не нужен.
4. Post-check: ревизия/таблицы, readiness :8001/:8002/:8004, реальные PID и новые
   ошибки, затем пользовательский сценарий «запомни → другой диалог → исправь → забудь».

Безопасный функциональный откат: вернуть флаг 0 и перезагрузить затронутые процессы.
Новые таблицы и данные оставить, не выполнять destructive downgrade в production.
Применение миграции и включение не выполняются при старте процесса.

## Проверка

Изолированный HTTP/worker gate:
`python output/ai-smart-memory-20261008/run_checks.py`.
Он копирует существующую пустую тестовую схему и реально применяет новую ревизию.
`tests/test_ai_smart_memory_migration.py` отдельно проверяет upgrade, повторный
upgrade, ограничения и downgrade с сохранением прежних фактов.

Полная историческая цепочка Alembic на пустой SQLite пока упирается в прежнюю
`20260330_0013` (обращение к PostgreSQL-схеме app). Эта посторонняя миграция не менялась.
Новая ревизия применена и проверена на production PostgreSQL 08.10.2026 по
разрешению пользователя. Флаг включён, личная память пользователя 38 включена;
четыре целевых процесса обновлены, readiness и PostgreSQL realtime готовы,
посторонние PID и счётчики рестартов сохранены. Post-check: ноль новых ERROR/Traceback.
Отдельного PostgreSQL staging и реального пользовательского диалога после включения
не проверяли. Доказательства: `output/ai-smart-memory-20261008/postcheck.json`.
