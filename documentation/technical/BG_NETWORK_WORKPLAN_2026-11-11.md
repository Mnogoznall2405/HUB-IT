## 3. Блок A. Сеть, Wi-Fi, лимиты

### A-01. STP/RSTP: приоритеты и дерево (P0)

Цель: один корень (GW 75.1), предсказуемая топология, без петель и «перескоков» root.

Заданная иерархия из перечня:

| Устройство | Приоритет по перечню | Комментарий |
|---|---|---|
| GW 75.1 | 0 | корень |
| 75.3 | 1024 | следующий уровень |
| 75.9 (медик) | 2048 | адрес уточнить по факту |
| Столовая | 4096 | |
| Балок 5 (Талгат, точка для рабочих) | 4096 | как у столовой |
| Доп. штаб АСУ / автоматика / КАБ | следующий по расчёту | выдать после проверки текущих |
| Остальные Wi-Fi точки | 8000 либо NONE | «протокол работает лучше» |

**Техническая нестыковка, требует решения до настройки.** В MikroTik приоритет моста задаётся с шагом **4096** (0, 4096, 8192, 12288 …). Значения **1024, 2048 и 8000 в этот шаг не попадают**: они либо недопустимы, либо усекаются, и тогда 75.3/75.9 получат тот же эффективный приоритет, что и GW (0). Это риск второго «корня» и нестабильного дерева.

Предлагаемая раскладка (эквивалентна замыслу, но валидна):

| Устройство | Предлагаемое значение |
|---|---|
| GW 75.1 | 0 |
| 75.3 | 4096 |
| 75.9 (медик) | 8192 |
| Столовая и балок 5 | 12288 (равны, как в перечне) |
| Доп. штаб АСУ / автоматика / КАБ | 16384 |
| Остальные Wi-Fi точки | 32768, при отсутствии колец — `protocol-mode=none` |

Значения 1024/2048/8000 согласовать с Никулиным: возможно, в перечне имелись в виду path cost портов, а не приоритет моста.

Порядок:

- [ ] Снять текущие значения: `/interface bridge print detail`, `/interface bridge port print detail`.
- [ ] Проверить, где реально есть кольца, а где STP можно отключить (`NONE`).
- [ ] Согласовать раскладку.
- [ ] Менять по одному устройству, от периферии к корню, с паузой и проверкой.
- [ ] После каждого шага: один root, нет `topology change` в логе, связность есть.

Проверка: `/interface bridge monitor <bridge> once`, `/log print where topics~"stp"`, ping/трейс до ключевых сегментов.

**Терминология.** В перечне написано «RTSP», но по контексту (bridge, STP, приоритеты) речь про **RSTP** — Rapid Spanning Tree. RTSP — протокол видеопотока, к приоритетам моста отношения не имеет.
