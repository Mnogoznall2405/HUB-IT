# Очередь доставки и офлайн-навигация: продолжение PR #5

База: ca755a9884ac6230d08bd3ade59b226344630018. Только отдельная ветка; main, production и APK не меняются.

## Реализация

Добавлен session-owned отправитель вне экрана диалога. Новое явное намерение отправить хранится в необязательных метаданных delivery версии 1; старые записи остаются ручными. Ожидание, ограниченный повтор, пауза, отмена и подтверждённое сообщение различаются. HTTP и прогресс не принадлежат жизненному циклу диалога. Два диалога обслуживаются независимо, FIFO внутри диалога сохраняется.

ACK удерживается до проверки записи сообщения в локальную историю. Сбой локального сохранения не вызывает повторный HTTP в текущем процессе. После перезапуска используется сохранённый ACK либо прежний client_message_id, поэтому серверная идемпотентность остаётся обязательной.

Сетевые попытки выполняются только при подходящей сессии, правах, активном разблокированном приложении и отсутствии офлайна. Работа из force-stopped приложения не реализована. Уже принятый сервером текст нельзя отменить задним числом. Cancel файлового запроса использует AbortSignal.

Существующая реализация метаданных/копирования сохранена в nativeChatOutboxLegacy.ts без изменения. Новый фасад добавляет управление доставкой, не стирает старую очередь, не меняет шифрование, зависимости или серверный API.

Подключение экранов включает немедленный однократный back, локальный jumpToBottom, защиту устаревшего поиска внутри диалога и списка, устойчивое сохранение истории при уходе, честный cache miss и route key с пользователем.

## Проверки и применение

Скрипт apply-chat-followup.py проверяет Git blob SHA и точные участки исходников, готовит все изменения до записи и по умолчанию работает в dry-run. Он не обращается к сети и не выполняет commit/deployment. Одноразовый workflow применяет его только в ветке fix/chat-offline-history-safety-2026-09-07, устанавливает штатные locked зависимости без lifecycle scripts и запускает проверки. Изменения экранов фиксируются только после успешных APPLY, LOGIC и LINT; результат записывается в CHAT_DELIVERY_BRANCH_CHECKS.md. До появления этого отчёта интеграция не считается выполненной.

Добавлено 17 проверок реальных модулей очереди/runner с native-границами в памяти, 8 проверок реальных callback-функций экрана и 1 статическая проверка debounce/flush. Их результат для текущего фасада не подменяется результатами предыдущего прототипа. Проектные Jest-тесты дополнены композиционным хостом доставки; утверждения не удаляются и не пропускаются.

Фактический результат текущего запуска следует брать из CHAT_DELIVERY_BRANCH_CHECKS.md и GitHub Actions. Android, APK и production: NOT RUN.
