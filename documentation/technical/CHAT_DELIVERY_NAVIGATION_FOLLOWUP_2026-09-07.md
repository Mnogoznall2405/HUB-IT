## Реализация

Добавлен отправитель в авторизованной оболочке, вне экрана диалога. Новое явное намерение отправить хранится в необязательных метаданных delivery версии 1; старые записи остаются ручными. Ожидание, ограниченный повтор, пауза, отмена и подтверждённое сообщение различаются. HTTP и прогресс не принадлежат жизненному циклу диалога. Два диалога обслуживаются независимо, FIFO внутри диалога сохраняется.

ACK удерживается до проверки записи сообщения в локальную историю. Сбой локального сохранения не вызывает повторный HTTP в текущем процессе. После перезапуска используется сохранённый ACK либо прежний client_message_id; серверная идемпотентность остаётся обязательной.

Сетевые попытки выполняются только при подходящей сессии, правах, активном разблокированном приложении и отсутствии офлайна. Работа из force-stopped приложения не реализована. Уже принятый сервером текст нельзя отменить задним числом. Cancel файлового запроса использует AbortSignal.

Существующая реализация метаданных/копирования сохранена в nativeChatOutboxLegacy.ts без изменения. Новый фасад добавляет управление доставкой, не стирает старую очередь, не меняет шифрование, зависимости или серверный API.

Экранные правки: немедленный однократный back, локальный jumpToBottom, защита устаревшего поиска внутри диалога и списка, устойчивое сохранение истории при уходе, честный cache miss и route key с пользователем. Экран очереди использует общий отправитель, а не отдельный конкурирующий HTTP-путь. Автоматически не отправляются старые ошибки/отменённые записи без нового явного намерения.

Подробности сохранены в CHAT_DELIVERY_BRANCH_CHECKS.md.

После применения исходников одноразовый изменяющий ветку workflow удалён. На его месте обычная проверка с contents:read, без push/commit, без генерации исходников. Она не подменяет HTTPS-адрес приложения, а блокирует удалённые Node-соединения тестового процесса. При провале Jest выполняется сравнение исходной базы в той же среде; итоговый check остаётся красным при провале текущих тестов.

17 проверок выполняют реальные модули очереди/runner с native-границами в памяти. Ещё 8 выполняют реальные callback-функции экрана; 1 проверяет подключение debounce/flush статически. Это не Android и не замена экранным Jest-тестам. Существующая Jest-обвязка монтирует реальный session-owned хост доставки; утверждения не удалялись и не пропускались.

Финальный результат полного Jest следует брать из последнего Actions запуска и итогового отчёта ревью. Android, APK и production: NOT RUN.
