# HUB-IT: исправление сохранности офлайн-истории

База: `927ae8673aecf9e4fd6253c5ea1d1fe0187a74f7`.
Дата: 7 сентября 2026 года.
Статус: точечный пакет для отдельной ветки и чернового PR. Не полное завершение офлайн-чата.

## Что исправлено

1. `mobile-hub/src/chat/nativeChatThreadHistory.ts`: ограничение 1500 сообщений теперь сохраняет начало массива newest-first, а не хвост. Новые сообщения больше не отбрасываются вместо старых.
2. `mobile-hub/src/offline/nativeOfflinePreparation.ts`: подготовка истории использует `scheduleNativeChatThreadSnapshotWrite`, который объединяет страницу с накопленной историей. Ранее сохранённые 500 сообщений не заменяются последними 80. Поколение истории захватывается перед запросами, чтобы поздний ответ подготовки после инвалидирования поколения не записывал историю.
3. `mobile-hub/src/offline/nativeReadCacheRefresh.ts`: свежесть позволяет пропустить обновление только полного каталога (`has_more === false`). Недавняя первая страница больше не откладывает догрузку на шестичасовой интервал.

Существующий лимит хранения сохранён. Формат данных, шифрование, зависимости, авторизация и настройки сервера не менялись. Очистка пользовательских данных не выполнялась. Уже вытесненные старой версией сообщения этот пакет автоматически не восстанавливает — их нужно получить с сервера.

## Что остаётся открытым

Автодоставка очереди при reconnect, отдельный статус ожидания сети, офлайн-путь вложений, защита двойного «назад» в экране, локальный `jumpToBottom`, устаревшие ответы поиска, лишние записи из экранного cleanup, полноценные диапазоны истории и позиция просмотра в этот пакет не вошли.

Поколение подготовки защищает позднюю постановку thread-write. Это не доказательство устранения всех гонок logout: уже начатый низкоуровневый I/O, каталог и другие модули имеют отдельный жизненный цикл.

Перед merge нужны проектные проверки. Перед выпуском APK — Android-проверка. `main` и production этим пакетом напрямую не изменяются.
