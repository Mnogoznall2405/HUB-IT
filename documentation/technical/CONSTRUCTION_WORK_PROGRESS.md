## Согласованный объём

Ежедневный учёт ведётся в HUB-IT. Excel служит образцом структуры, не обязательным рабочим инструментом.
План и накопленный исходный факт можно ввести в HUB-IT. Автоматический перенос произвольных Excel-формул не выполняется.

Направление принадлежит управляемому объекту строительства. Работы группируются в разделы.
Запись факта — абсолютный объём за выбранный день (одна суточная запись на работу), а не команда прибавления.
Повторное сохранение не удваивает объём. Изменение устаревшей версии отклоняется с HTTP 409.
Пакет строк сохраняется атомарно. История хранит пользователя, время и предыдущее/новое значение.

Действующие construction.read/write сохраняются. Отдельный процесс утверждения и новые права не вводятся без согласования.
Процент работы = накопленный факт / план × 100; превышение плана показывается явно.
Сводная готовность = среднее процентов работ с заданными положительными весами, с ограничением вклада каждой работы 100%.
Вес — относительная доля работы, которую задаёт составитель плана (например, по плановой трудоёмкости).
Если веса или план не заполнены для всех работ, сводный процент отсутствует; интерфейс объясняет причину.
Проценты снабжения, строительных работ и исполнительной документации не смешиваются.

## Реализация

- `app.construction_work_items`: стабильный UUID работы, объект и группа 1С, версия, план в `plan_json` (валидируется `WorkPlan`).
- `app.construction_work_entries`: фактический объём `NUMERIC(18,4)`, дата и суточные данные; UNIQUE `(work_id, work_date)`, FK на работу.
- `app.construction_work_audit`: неизменяемая история плана/факта, автор и время, значения до/после; FK на работу.
- Миграция `20260908_0108` после `20260907_0107`, scope `app`; schema-changing операции в request path не добавлены.
- API: `GET objects/{id}/work-progress` и `GET objects/{id}/directions/{group}/work-progress`; `PUT .../work-plan`, `PUT .../work-days`, `GET .../work-items/{work}/history` в `/construction`.
- Перед записью оба сервиса блокируют объект, затем направление; изменение версии проверяется атомарным UPDATE. Направление с любыми сохранёнными работами нельзя отвязать.
- План, факт выбранного дня, накопленный объём и тренд читаются одним SQL statement snapshot. Историческая кривая пересчитывается по текущему плану/весам.
- До 300 изменений в одном атомарном пакете, до 5000 работ объекта; история читается страницами с cursor.
- Начальный накопленный факт задаётся вместе с датой; суточные записи допускаются только после неё, чтобы не удваивать объёмы.
- Суточный ввод сохраняется при переключении вкладок направления. Уход на другую страницу/назад требует подтверждения, закрытие окна предупреждает о несохранённом вводе. Ошибка сохранения не стирает поля.
- Архивирование и восстановление выполняются с подтверждением и проверкой версии. Архив сохраняет факт/историю, исключается из готовности; GET `include_archived=true` возвращает его для просмотра и восстановления.
- Фактические даты не могут быть будущими. Единицу измерения нельзя менять после внесения ненулевого выполненного объёма.
- Объёмы отображаются с точностью до четырёх знаков после запятой, проценты — до двух. Обновление таблицы завершается и при временно скрытой вкладке; после переименования раздела исчезнувший фильтр сбрасывается на все разделы.
- Настройки объекта отправляют `expected_updated_at`; устаревшая форма получает 409 и сохраняет ввод. Фоновое обновление родителя не сбрасывает открытую форму. Ошибка загрузки блокирует сохранение и позволяет повторить запрос. Уход с несохранёнными настройками через SPA/Back требует подтверждения; во время сохранения он заблокирован, успешное сохранение разрешает переход к созданному объекту.
- Фильтры заявок сохраняются при автоматическом/ручном выборе и возврате. Выбор склада снабжения открывает его заявки. Карточка сотрудника открывается кнопкой имени, поддерживает Escape и возврат фокуса.

# Расчёт первого листа «Сводного» — 08.09.2026

среднее процентов 24 перечисленных в ней разделов. Остальные листы и нижний
блок 583/2 не участвуют. Исходный результат: 91.59707083663022% (91,60%).

`prepare-first-sheet-calculation.py` разбирает только проверенную арифметику
SUM, ссылки, сложение и умножение на постоянные коэффициенты. Python eval и
чтение Excel в API не используются. Компилятор сверяет каждый из 24 разделов

работ и коэффициентами числителя/знаменателя. Runtime берёт текущие плановые
и накопленные объёмы из журнала. Перевыполнение не ограничивается 100%.

Профиль хранится в существующей `app.app_settings` под ключом
`construction.work_calculation.<object_id>` и применяется только к указанному
направлению. В обзоре объекта явно подписана область показателя. Другие работы
сохраняются; их количество показано как не включённое в расчёт. Новые работы,
не входящие в профиль исходника, автоматически не меняют эту формулу.
Отсутствие/архивирование ожидаемой работы или нулевой план раздела дают
отсутствующий расчёт с объяснением, а не нулевой/частичный процент.

исходного расчёта»; изменение дочерних строк не заменяет ручной итог Excel.
