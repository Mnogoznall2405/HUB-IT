# План редизайна «Мои файлы»

Основание: `FILES_UI_REDESIGN_AUDIT.md`. Принцип: безопасный рефакторинг —
сохраняем все хендлеры/API/модель прав, пересобираем JSX-зоны и отдельные компоненты.
API и backend не меняются.

## Целевая компоновка

```
┌──────────┬────────────┬───────────────────────────────┬──────────┐
│ Зона A   │ Зона B     │ Зона C (рабочая область)      │ Зона D   │
│ MainLayout│ Файл.     │ Поиск                         │ Сведения │
│ (не       │ навигация │ Хлебные крошки + действия     │ (панель) │
│ трогаем) │ 240-260px │ Фильтры + вид + bulk-панель   │ 300px    │
│          │            │ Таблица/сетка                 │          │
└──────────┴────────────┴───────────────────────────────┴──────────┘
```

## Рабочие пакеты

### WP1. Компоновка и навигация (MyFiles.jsx + новый компонент)

- Вынести левую панель в `components/myFiles/MyFilesSidebar.jsx` (пропсы: view, libraries, quota, колбэки). Содержимое без изменений, единый стиль выбранного пункта.
- ≥lg (1200px): панель 252px как сейчас + **кнопка сворачивания** → rail 64px (только иконки с tooltip; «Создать» → FAB-иконка; квота скрыта).
- <lg: панель → **MUI Drawer** (`temporary`), триггер — иконка-меню в панели инструментов контента (рядом с хлебными крошками). Никакого горизонтального блока.
- <lg содержимое Drawer = тот же компонент сайдбара (полная ширина 280px).
- Состояние свёрнутости в localStorage `my-files-nav-collapsed`.

### WP2. Рабочая область (зона C)

- Одна строка панели инструментов: [меню-иконка <lg] · хлебные крошки · spacer · [поиск — перенести сюда] · [фильтры Тип/Изменено] · [вид список/сетка] · [сведения i] · [обновить].
- Поиск: компактный rounded-инпут в тулбаре (как Drive), на xs — на всю ширину под тулбаром.
- Заголовок раздела — из хлебных крошек/чипа роли (как сейчас), без дублирующего гигантского H1.
- Bulk-панель остаётся на месте (`my-files-selection-bar`).
- Никаких `max-width` ограничений у контента.

### WP3. Разгрузка строк + панель сведений (MyFilesListItems.jsx + новый MyFilesDetailsPanel.jsx)

- Из под-имени строки убрать чипы «Совместно»/«Ссылка»/«Навсегда»/retention-текст. Оставить: имя+иконка типа (основная строка), справа мини-иконки состояния (shared — People, link — Link, retention-warning — Schedule только при ≤7 дн.) — компактно, 16px, без текста.
- Критичный срок (<3 дн.) — короткий красный чип «N дн.» в колонке «Изменён» либо та же иконка красным — предупреждение не теряем.
- Новый `MyFilesDetailsPanel.jsx`: aside 300-320px справа от контента (≥xl) или overlay-Drawer (<xl), toggle кнопкой «Сведения» в тулбаре и пунктом меню/двойным i в строке.
- Содержимое (всё из существующих данных): иконка/мини-превью, имя, тип, размер, владелец, изменён/создан, расположение (breadcrumbs), срок хранения и дата удаления, статусы (публичная ссылка, совместный доступ, processing), library + роль при просмотре общей папки. Для multi-select — «Выбрано N объектов» + сводный размер.
- Кнопки быстрых действий сверху панели: Открыть/Скачать/Поделиться/Ещё (тот же FileActionsContextMenu).

### WP4. Диалог общей папки (MyFilesLibraryDialog.jsx)

- Ширина ~760px (`maxWidth="md"` + `fullWidth`), `height ≤ calc(100dvh - 64px)`, fullScreen <sm.
- Шапка (фикс): название папки + закрыть. Под шапкой — `Tabs`: «Основные» / «Доступ».
- «Основные»: поле Название (обязательное), поле «Лимит хранения, ГБ» с helper «Пусто — без отдельного лимита; файлы общей папки хранятся бессрочно и учитываются в лимите папки, а не личных квотах участников» (строго по backend-семантике `quota_bytes`), индикатор занято/лимит (из `used_bytes/quota_bytes` списка библиотек), danger-зона «Удалить общую папку» (только глобальные менеджеры; кнопка + подтверждение последствий, только для пустой папки — по API).
- «Доступ»: поиск по сотрудникам и подразделениям в одном поле (две секции результатов или два автокомплита как сейчас — выбрать менее расторможенное, минимум: единая строка «Добавить людей и подразделения»), выбор роли с **видимым** описанием ролей (текстом, как в CollaboratorsDialog — устранить расхождение с tooltip-only).
- Список участников в две секции: «Подразделения» (название, N участников, роль, expand состава — API есть) и «Сотрудники» (ФИО/логин, роль-Select, ⋮-меню: Изменить роль → встроенный Select, Удалить). Никаких одиноких крестиков.
- Режим `membersOnly` (manage-участник без глобального перма) → только вкладка «Доступ», заголовок «Управление доступом».
- Футер (фикс): счётчик несохранённых изменений + «Отмена»/«Сохранить»; двойной сабмит блокировать; при закрытии с несохранённым — подтверждение.
- Ошибки сервера — под соответствующим полем/вкладкой, не только тост.

### WP5. Меню и мелочи

- Слить два folder-меню в один рендер с условными пунктами; опасные действия — внизу после Divider.
- Пункт «Сведения» в контекстные меню файла и папки → открывает панель.
- Фиксы из аудита §6.9-6.14 (иконка корзины в сетке, dead imports, isCurrent в хуки, testid, дубль beforeunload) — только если безрисково в рамках правок.

### WP6. Адаптивность и доступность

- Брейкпоинты: xs drawer-навигация; md — контент + скрытие owner/size (уже); lg — сайдбар 252; xl — + панель сведений.
- Сортировка клавиатурно (TableSortLabel — уже button); Drawer — Esc/фокус-ловушка MUI; панель сведений — Esc и aria-label «Панель сведений».
- Все иконки-кнопки с aria-label (проверить новые).
- Проверки: 1920/1440/1366/1024/768/390 + zoom 125/150/200.

## Что НЕ меняем

- API, payload, модель ролей/мержа прав, PUT-полной-замены участников.
- MainLayout/зона A, мобильный bottom-nav.
- Хуки upload/download/shares/preview (кроме передачи isCurrent — багфикс).
- Локализация: все новые строки — русские литералы как в соседнем коде (i18n-фреймворка в файле нет).
