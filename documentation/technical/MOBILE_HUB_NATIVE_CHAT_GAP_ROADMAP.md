| Поле | Значение |

| Дата | 2026-08-24 |
| Область | Android `mobile-hub` native Chat |

Связанные документы: [MOBILE_HUB_NATIVE_CHAT_PLAN.md](./MOBILE_HUB_NATIVE_CHAT_PLAN.md), [CHAT_BACKEND_ARCHITECTURE.md](./CHAT_BACKEND_ARCHITECTURE.md).

Nekogram и Telegram — только поведенческий и визуальный референс. Код, assets и брендинг не копируются. Для ревизии использован отдельный временный checkout официального Nekogram; в репозиторий HUB-IT он не добавлялся. Source of truth по функциям HUB-IT — **web-чат** и существующий Chat API.

По палитре решение принято 2026-08-23: нативный Chat живёт на собственных токенах `mobile-hub/src/theme/chatTokens.ts`, близких к Telegram. Права, термины и сущности остаются HUB-IT. Подробнее — принцип 1 в [MOBILE_HUB_NATIVE_CHAT_PLAN.md](./MOBILE_HUB_NATIVE_CHAT_PLAN.md).

## Зачем этот файл

Нативный Chat читает и пишет в те же диалоги, что web. Основной мобильный слой уже добавлен: папки, выделение, Back/edge-swipe, голосовые, редактор фото, multi-file preview и viewer. Актуальный незакрытый риск — физическая Android-проверка жестов, клавиатуры, TalkBack и сетевых переходов.

Файл фиксирует разрыв **web ↔ native ↔ Telegram/Nekogram** и отделяет то, что решается только в мобильном коде, от того, что требует решения по backend.

## Правила

1. Сначала закрыть то, что уже есть в web и мешает ежедневному использованию.
2. Жесты обязательны, но у каждого есть видимая кнопка или пункт меню.
3. Свайпы не конфликтуют: назад, ответ, пересылка, папки и прокрутка — разные зоны и пороги.
4. Не проектировать новый backend там, где web уже ходит в существующий контракт.
5. Не тащить из Telegram stories, секретные чаты, каналы, scheduled/silent send и клон интерфейса.

## Что уже есть в native 1.1.11

- inbox и thread, realtime, optimistic send, retry и HTTP catch-up после reconnect;
- ответ / правка / удаление / пересылка и меню из 5 быстрых реакций с раскрытием до 16;
- свайп вправо — ответ, свайп влево — пересылка, haptic на пороге;
- long press включает выделение, tap добавляет сообщения; действия доступны через якорное floating-menu у пузыря;
- поиск по текущему диалогу;
- камера, галерея, файл, voice, GIF и редактор изображения;
- до 5 вложений одним сообщением: локальный пузырь появляется до ответа сети, preview и подпись не блокируют композер, а cancel и idempotent retry сохраняют `client_message_id`;
- файлы в сообщении отображаются отдельной Telegram-like карточкой с типом, именем, размером и независимым прогрессом; загрузку и скачивание можно отменить или повторить прямо в карточке, tap скачивает и открывает файл, меню сохраняет сценарии open/share/save;
- выбор через системный document picker сохраняет `media_kind=file`, поэтому фото, видео, аудио и стикер-файлы, отправленные как документ, не превращаются в inline-медиа;
- стикеры, emoji, упоминания, карточка Hub task, AI confirm/cancel;
- mute / pin / archive диалога, серверное закрепление сообщения;
- группировка пузырей, даты, разделитель непрочитанных, кнопка вниз;
- системные и пользовательские папки, отдельные «Непрочитанные», архив и AI, свайп между вкладками;
- long press по строке диалога открывает видимое меню pin / mute / archive / folders как альтернативу скрытым свайпам;
- полноэкранный media viewer: соседние слоты, пагинация manifest, auth-заголовки, pinch/double-tap zoom, bounded pan, horizontal paging и downward dismiss;
- progressive media: сначала preview, затем авторизованный original с мягкой подменой;
- heartbeat deadline закрывает зависший WebSocket, а thread/inbox используют HTTP polling до восстановления realtime;
- нижний якорь ожидает реальный `onContentSizeChange`, а изменение высоты композера удерживает ленту только когда пользователь у низа.

Оставшийся блокер выпуска в стабильный канал — обязательная приёмка на физическом Android. Stories, секретные чаты, каналы и scheduled/silent send сознательно не входят в продуктовый scope HUB-IT.

### Правила конфликта

1. **Назад** ловится только у левого края (~20–28 dp). Иначе ломается свайп «ответить».
2. **Ответ / пересылка** стартуют на пузыре, когда горизонталь заметно больше вертикали (текущий порог: `|dx| > 8` и `|dx| > |dy| * 1.4`, срабатывание на 44 dp).
3. **Вертикаль** принадлежит списку: при прокрутке горизонтальные жесты отменяются.
4. В **режиме выделения** свайпы пузыря выключены, tap только переключает выбор.
5. В **viewer** жесты принадлежат просмотру; Back закрывает viewer, а не диалог.
6. У каждого жеста есть видимая альтернатива: стрелка назад, «Выбрать», вкладки папок, пункты меню.
7. Reduced motion: без полёта элементов, мгновенная смена состояния; haptic сохраняется.

### Действие «назад» — выйти из чата

Сейчас системный Back, стрелка и edge-swipe используют один стек слоёв: сначала закрывают viewer/sheet/search/selection, затем возвращают в inbox.

Нужны три согласованных пути: системный Back и жест навигации Android, стрелка в шапке, свайп от левого края.

```text
viewer / sheet / поиск / режим выделения
        ↓ Back
переписка
        ↓ Back или edge-swipe
список диалогов (та же папка, та же позиция)
        ↓ Back
портал HUB-IT
```

Критерии:

- из диалога пользователь попадает в inbox, а не на дашборд;
- активная папка и позиция списка сохраняются;
- клавиатура закрывается до ухода, черновик остаётся;
- открытый слой закрывается первым Back;
- edge-swipe не стартует с кнопки, вложения и композера и не перехватывает reply-swipe.

Референс: `ChatThread.jsx` (web edge-swipe), `app/portal.tsx` (готовый пример `BackHandler`).

## Папки как в Telegram — верхняя полоса

Нужны не чипы «Все / Непрочитанные», а узкая полоса вкладок сверху: пилюли, активная подсветка, счётчик непрочитанных, свайп между папками.

Web уже так устроен: системные вкладки **Личные / Беседы / Задачи**, затем пользовательские папки, архив отдельно, AI не смешивается с обычными диалогами. API `/chat/folders` (список, создание, переименование, состав) существует.

```text
[ ← ]  Chat                         [ + ]
Личные   Беседы   Задачи   Работа   Склад
 ──●──
[ поиск по текущей папке                 ]
диалог
диалог
```

- полоса под шапкой, над поиском, с горизонтальным скроллом;
- активная вкладка — «островок»: заливка-пилюля и вес текста;
- unread badge на вкладке, как в web `ChatFolderTabs`;
- свайп по списку или по полосе переключает соседнюю вкладку;
- состав папок берётся из `/chat/folders`, новые ключи не выдумываются;
- управление папками — из меню inbox.

| Ключ | Состав |
|---|---|
| `personal` | direct + notes |
| `unread` | все непрочитанные неархивные диалоги |
| `groups` | group |
| `tasks` | диалоги задач |
| пользовательская | `conversation_ids` с сервера |
| `archived` | только архив, отдельно от основного ряда |

«Непрочитанные» реализованы отдельной системной вкладкой, а не вторым фильтром внутри выбранной папки.

**Счётчики папок.** Решение реализовано на сервере: `/chat/folders` возвращает `folder_unread_counts` по системным папкам. Native использует эти значения, а сумму по загруженным диалогам сохраняет только как fallback.

## P0 — реализовано, нужна device-приёмка

### 1. Посадка исходящего сообщения

Исходная причина была найдена в `NativeChatThreadScreen.tsx`: список одновременно использовал:

- `inverted`;
- `maintainVisibleContentPosition={{ minIndexForVisible: 0 }}`;
- после отправки вызывает `scrollToOffset({ offset: 0, animated: true })` через `requestAnimationFrame`.

В инвертированном списке новое сообщение вставляется индексом 0, а `minIndexForVisible: 0` просит удержать на месте прежний элемент этого индекса. Пузырь появляется ниже видимой области, и только последующий анимированный доскролл поднимает его. Дополнительный источник дёрганья — `onLayout` композера, который снова просит якорь при каждом изменении высоты (режим ответа, строка загрузки).

Реализованное решение:

- `maintainVisibleContentPosition` включается только при догрузке старых сообщений;
- собственная отправка ставит нижний якорь без анимации после фактического `onContentSizeChange`;
- изменение высоты композера запрашивает якорь только когда пользователь уже у низа;
- сценарии вставки, prepend и высоты композера покрыты тестами `chatListAnchor` и `NativeChatScreens`.

Готово, когда отправка, смена высоты поля и открытие клавиатуры не двигают уже видимое последнее сообщение.

### 2. Выделение как в Telegram

1. Удержание ~400 мс выделяет сообщение: фон, галочка, haptic.
2. Шапка сменяется панелью: счётчик, «Ответить» (при одном), «Переслать», «Копировать», «Удалить».
3. Следующие tap добавляют и снимают выбор.
4. Back или «Готово» сбрасывает режим.
5. Меню реакций и действий остаётся доступным, но выделение становится основной реакцией на удержание.

Права на удаление берутся из тех же правил, что в web (`canDeleteChatMessage`), а не решаются на клиенте заново.

Референс: `useChatSelectedMessageActions.js`, `chat-selection-toolbar`.

### 3. Полноэкранный просмотр фото

Tap по картинке открывает viewer внутри приложения вместо системного `Alert`.

Первый проход: фото на весь экран, закрытие Back и кнопкой, действия «сохранить / поделиться / переслать», подпись с автором и временем. Следом: листание соседних фото, pinch-zoom, закрытие свайпом вниз.

Текущие действия с вложением (открыть, поделиться, сохранить в «Мои файлы») сохраняются, но переезжают в меню viewer.

### 4. Жест и действие «назад»

См. раздел выше. Единый стек Back реализован для viewer, меню, поиска, выделения и выхода в inbox.

### 5. Полоса папок сверху

`ChatFolderTabs` подключён к `/chat/folders`; свайп переключает соседние системные и пользовательские папки, а системные badge используют серверные `folder_unread_counts`.

## Фазы

### Фаза A — жесты и якорь — реализовано, нужна device-приёмка

Посадка исходящего сообщения, Back и edge-swipe, выделение с пакетными действиями, viewer по tap, полоса системных папок со свайпом.

Готово, когда сценарий проходит целиком: открыл папку, вошёл в диалог, ответил свайпом, выделил несколько сообщений, посмотрел фото, вышел свайпом назад — без прыжка исходящего пузыря.

### Фаза B — parity с web — основной объём реализован

Пользовательские папки, отделение архива, серверный поиск inbox по `q`, голосовые, редактор фото перед отправкой, typing, галерея медиа в сведениях диалога, листание и pinch-zoom в viewer, разделение notes / task / support / AI.

### Фаза C — полировка — реализовано, нужна device-приёмка

Double tap на реакцию, свайп строки inbox, глобальный поиск и GIF реализованы. Контекстные действия открываются в якорном floating-menu у пузыря; доступны 5 быстрых реакций и раскрытие полного набора из 16 с touch targets не меньше 44 dp.

## Решения приняты

Все пять вопросов этого раздела закрыты 2026-08-23.

| Вопрос | Решение |
|---|---|
| Закреплённое сообщение | Серверный pin, общий для участников: новые поля в `chat_conversations` и `PUT /chat/conversations/{id}/pinned-message`. Локальное хранилище — только fallback до ответа сервера |
| Счётчики непрочитанных на вкладках папок | Серверные счётчики: `/chat/folders` отдаёт `folder_unread_counts` по системным папкам. Сумма по загруженным диалогам осталась запасным вариантом |
| Глобальный поиск по сообщениям | Заведён `GET /chat/messages/search` по всем диалогам участника. Native использует его в inbox; web-UI пока не подключён |
| Архив | Отдельная вкладка в конце ряда папок, вне последовательности свайпа |
| Голосовые | Реализованы на `expo-audio` с разрешением `RECORD_AUDIO`; запись, отправка и воспроизведение работают |

Развёртывание серверного pin требует порядка: сначала миграция `20260823_0103`, затем рестарт backend. Поля объявлены в ORM безусловно, поэтому код на непромигрированной базе уронит весь чат.

## Риски

| Риск | Мера |
|---|---|
| Edge-swipe назад перехватывает reply-swipe | Узкая зона у края, тесты на пороги обоих жестов |
| Свайп папок конфликтует с прокруткой списка | Порог по горизонтали и отмена при вертикальном движении |
| Правка якоря списка ломает догрузку старых сообщений | Раздельные сценарии prepend и вставки нового; тесты на оба |
| Режим выделения ломает существующие действия | Свайпы отключаются только внутри режима, меню сохраняется |
| Папки расходятся с web | Ключи и состав берутся из `/chat/folders` и `chatFolderUtils.js`, дублирующая логика не заводится |
| Viewer тянет тяжёлую зависимость | Сначала минимальный экран на текущих средствах, библиотека только при подтверждённой необходимости |

## Приёмка

Проверять на физическом Android, не только в эмуляторе.

1. Отправка 10 сообщений подряд: ни одно не появляется ниже композера и лента не дёргается.
2. Свайп от левого края выходит в inbox; свайп по пузырю по-прежнему отвечает и пересылает.
3. Android Back закрывает слои по стеку и уводит в inbox, а не на дашборд.
4. Long press выделяет, tap добавляет второе сообщение, пересылка и удаление работают пакетом.
5. Фото открывается на весь экран и закрывается Back и свайпом вниз.
6. Полоса «Личные / Беседы / Задачи» плюс пользовательская папка совпадает с web; свайп меняет вкладку; поведение badge соответствует принятому решению.
7. Reduced motion и TalkBack: все жесты доступны кнопками, touch targets не меньше 44 dp.
8. Архивный диалог не появляется в обычной вкладке.
9. Два файла отправляются параллельно: у каждого свой прогресс; отмена одного не останавливает второй, retry сохраняет один пузырь без дубля.
10. Большое видео начинает воспроизводиться без ожидания полного скачивания; при несовместимом ответе срабатывает fallback.

Автотесты минимум на: пороги свайпов (back против reply против folder), состояние режима выделения, якорь инвертированного списка при вставке и при prepend, разбор ответа `/chat/folders`.
