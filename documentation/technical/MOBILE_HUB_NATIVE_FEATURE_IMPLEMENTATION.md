# HUB-IT Mobile — внедрение нативных функций Android

Статус: исполняемый план внедрения  
Дата: 2026-08-22  
Клиент: `mobile-hub/`  
Доставка: локальная сборка APK и внутренний HUB-IT feed

## 1. Цель

Довести Expo Android-клиент до стабильного внутреннего приложения: общий бизнес-интерфейс остаётся синхронным с мобильной web-версией, а APK добавляет функции, которые действительно должны быть нативными — безопасное обновление, биометрию, FCM, системные файлы, lifecycle, offline и Android permissions.

Критерий готовности функции: реализован код, есть узкие автоматические тесты, локальный release-вариант APK собирается, пройдена проверка артефакта и выполнена приёмка на физическом Android. Сборка без device-проверки не считается полной приёмкой.

## 3. Обновление APK из приложения

### Пользовательский сценарий

1. В `Настройки → Обновление приложения` отображаются установленная версия и build number.
2. Экран автоматически проверяет внутренний `latest.json`; пользователь также может нажать `Проверить обновления`.
3. Если версия новее, появляется кнопка `Скачать и установить <version>` и размер APK.
4. После подтверждения приложение скачивает APK в собственный cache и показывает прогресс.
5. До запуска установщика проверяются точный размер и SHA-256 из manifest. При несовпадении файл удаляется.
6. Android открывает системный установщик. Пользователь всегда сам подтверждает установку.
7. На Android 8+ система может один раз попросить разрешить `Установку из этого источника` для HUB-IT.

### Защитные ограничения

- manifest и APK принимаются только по HTTPS с `hubit.zsgp.ru`;
- разрешён только канал `/desktop-updates/mobile/preview/` и package `ru.zsgp.hubit.mobile`;
- manifest ограничен 16 КиБ, APK — 250 МиБ;
- путь, версия, MIME, размер и SHA-256 валидируются до установки;
- SHA-256 считается потоково по 512 КиБ, весь APK не загружается в JS-память;
- частичный или повреждённый APK удаляется;
- APK с другой подписью Android не установит поверх текущего приложения;
- silent install не используется: без device-owner/MDM Android требует системное подтверждение.

### Ограничение первого перехода

Опубликованная версия 1.1.3 ещё не содержит native updater. Поэтому 1.1.4 нужно один раз скачать обычной кнопкой из HUB-IT и установить вручную. Начиная с установленной 1.1.4 последующие версии можно получать через кнопку внутри приложения.

## 4. Реализованные пакеты и оставшиеся device-гейты

### Пакет N2 — уведомления и быстрые действия

Статус кода: реализован. Остаётся физическая FCM-приёмка на двух устройствах.

- отдельные Android channels: Chat, задачи, почта, системные события;
- корректная синхронизация FCM token на login/cold start/resume/rotation/logout;
- deep links из foreground, background и killed state без двойной навигации;
- Chat action `Ответить` с нативным text input, refresh token и идемпотентным `client_message_id`;
- module-scope notification task выполняет `Ответить`/`Прочитано` без открытия приложения; payload привязан к активному `userId`;
- ограниченная SecureStore-очередь сохраняет точный ответ при потере сети, показывает `Ответ сохранён` и даёт повторить отправку;
- Expo BackgroundTask/Android WorkManager повторяет только pending reply, `chat.mark_read`, push-token и badge с минимальным интервалом 15 минут;
- backend задаёт TTL/collapse key, package restriction и стабильные channel/tag/route metadata для FCM;
- Chat сохраняет события в собственной durable outbox, а задачи, почта и системные события — в `app.push_outbox`; очередь идемпотентна по получателю/channel/tag, повторяет временные ошибки с backoff и публикует backlog/heartbeat;
- privacy preview на заблокированном экране, mute и quiet hours;
- badge/unread reconciliation после открытия и прочтения.

Гейт: 50 уведомлений каждого типа на двух устройствах без потерь, дублей и неверных маршрутов.

### Пакет N3 — файлы, камера и Android share

Статус кода: реализован. Остаётся проверка Android permission/open/share и больших файлов на устройстве.

- нативные file picker, камера и галерея с корректными permissions;
- upload/download progress, отмена и повтор;
- открытие файлов через content URI/FileProvider;
- Android share sheet для файлов и ссылок;
- лимиты MIME/размера, безопасные имена и очистка временных файлов.

Гейт: Chat и почта проходят выбор, отправку, скачивание, открытие и повтор на Android 13+ без утечки временных файлов.

### Пакет N4 — offline lifecycle

Статус кода: реализован без опасных скрытых очередей. Остаётся cold-start/offline/online матрица на устройстве.

- время последней синхронизации и stale/cache-miss состояния;
- LRU для вложений и изображений с лимитом и ручной очисткой;
- точечный refresh текущего модуля после возврата сети;
- offline-команды только для явно идемпотентных операций с видимой очередью и конфликтами;
- никаких скрытых очередей для отправки письма, сообщения и опасных переходов задач без отдельного серверного контракта.

Гейт: 20 cold start и 20 циклов offline/online/background без blank screen, logout, потери маршрута и ложного успеха записи.

### Пакет N5 — системный UX и безопасность

Статус кода: реализован, кроме создания и резервирования постоянного release keystore. Остаются device accessibility/system UI проверки.

- app lock после настраиваемого таймаута фона;
- предсказуемый Android Back: история WebView → экран → выход;
- native permission rationale и переходы в точные Android Settings;
- системная тёмная тема, font scale и screen reader acceptance;
- haptic только для подтверждённых действий и ошибок;
- защищённый crash/diagnostic export без токенов, писем, сообщений и персональных данных;
- постоянная release-подпись и документированный recovery ключа.

Гейт: clean install/upgrade, accessibility smoke, background/foreground и security checklist на физическом устройстве.

## 5. Порядок каждого выпуска

1. Выбрать один вертикальный пакет функций и зафиксировать acceptance-сценарии.
2. Увеличить `version` и `versionCode`; не переиспользовать опубликованный номер.
3. Запустить TypeScript, полный mobile Jest, Expo dependency check и релевантные frontend/backend тесты.
4. Локально собрать APK с Firebase client config и постоянной подписью.
5. Проверить package, min/target SDK, version, certificate, размер и SHA-256 Android build tools.
6. Установить clean/upgrade на физический Android и пройти сценарии тестовой учёткой.
7. Сделать backup текущего feed manifest, опубликовать APK атомарно и проверить внешний HTTPS download/hash.
8. Зафиксировать, что проверено автоматически, что проверено на устройстве и что осталось непроверенным.

## 6. Рабочие полномочия и ограничения

В рамках согласованного mobile-контура можно локально собирать новые APK, использовать существующие тестовые учётки или создавать отдельные минимально привилегированные тестовые учётки, проходить login/2FA/biometric/Chat/почту/задачи/offline/FCM и публиковать прошедшие проверки APK во внутренний feed.

Production `.env`, PM2/IIS, база данных, backend restart и новая публикация требуют отдельного preflight и подтверждения перед выполнением. Секреты, Firebase keys, пароли, TOTP и signing credentials не записываются в Git, план, CLI-аргументы или отчёты.
