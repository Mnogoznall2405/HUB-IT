# Нативная почта Expo — план до ощущения Gmail

| Поле | Значение |
|---|---|
| Статус | Ревью, код не менялся |
| Дата | 2026-09-25 |
| Область | `mobile-hub`, только нативные экраны почты |
| Эталон | Ощущение Gmail Android: плотность, жесты, поиск, читатель. Не визуальный клон |
| Стек | Expo / React Native, Fluent-токены, Exchange через существующий API |
| Вердикт ревью | Block |

Решения от 2026-09-25:

- Сохраняем Fluent и папки Exchange. Категории Gmail, snooze и отложенную отправку не копируем: в API их нет.
- Свайп: вправо прочитано/непрочитано, влево архив. Удаление остаётся в выборе и меню.
- По умолчанию отдельные письма, не цепочки.

Связанные документы: [MAIL_LOAD_TEST.md](./MAIL_LOAD_TEST.md), [MOBILE_HUB_NONCHAT_OFFLINE_PERFORMANCE_AUDIT_2026_09_13.md](./MOBILE_HUB_NONCHAT_OFFLINE_PERFORMANCE_AUDIT_2026_09_13.md).

## Что уже есть

Входящие, поиск, фильтры, папки, смена ящика, выбор, свайп, undo, снимок списка, читатель HTML, вложения, быстрый ответ, черновики, печать, заголовки и EML. Серверные SLO почты уже описаны в `MAIL_LOAD_TEST.md`. Клиентский список не ждёт метаданные папок: это зафиксировано тестом `shows the inbox before optional folder metadata finishes`. Обновление списка не должно перерисовывать уже смонтированные строки: `NativeMailInboxPerformance.test.tsx`.

## Архитектура

Тонкие роуты, толстые экраны, чистый API-слой, богатый домен `src/mail`. Серверной логики в клиенте нет.

```
app/(shell)/mail/          роуты по 5 строк: index, [messageId],
                           conversation/[id], compose, folders, settings
  └─ src/screens/mail/     Inbox (1185 строк), Message (998),
                           Compose (1000), Conversation (576),
                           Folders, Settings
       ├─ src/components/mail/  строки списка, свайп, карточка письма,
       │                        HTML-body (изолированный WebView),
       │                        rich-редактор, получатели, quick-reply
       ├─ src/mail/             домен: nativeMailModel (метки, даты,
       │                        свайп, цитаты), папки, черновики compose
       │                        и quick-reply, transfer, HTML-санитайз,
       │                        файлы/вложения, подпись, печать, unread-события
       ├─ src/api/             mailApi (список, письмо, цепочки, папки,
       │                        read/unread, importance, move/bulk/delete/
       │                        restore, drafts, send, контакты),
       │                        mailMailboxesApi, mailConfigApi
       └─ кросс-слои: cache/nativeSnapshotCache (mail-inbox, entity),
                       realtime/hubRealtimeSocket.onMailChanged,
                       AuthContext (mail.access, offlineMode),
                       PreferencesContext (тема, плотность)
```

Потоки: фокус → snapshot `mail-inbox` → строки → API страница 50 → метаданные (summary всегда, дерево/вид раз в 60 с) → запись snapshot. Непрочитанные — локальный event-bus (delta/absolute) плюс realtime; подписаны inbox, message, conversation, дашборд, навигация, уведомления. Черновики — два контура (compose scope user+ящик+source+mode; quick-reply scope) плюс in-memory transfer в полный редактор. Внешние картинки блокированы по умолчанию.

Правила для доработок из этого плана:

- Сеть только в `api/`, правила и форматирование — в `mail/`, экраны — оркестрация.
- Перед фичами Gmail-diff (жесты, история поиска, очистка корзины) вынести из Inbox хуки `useMailList` и `useMailSelection`: экран уже 1185 строк.
- Не плодить третий контур черновиков; transfer остаётся in-memory.
- Unread правится оптимистично с откатом; новую арифметику счётчиков не добавлять без теста.
- Snapshot не расширять новыми телами и HTML; сначала лимит и эвикция по P6.

### Проблемы архитектуры

Сверено с кодом 2026-09-25. Код не менялся.

P1. Экраны-боги. Inbox 1185 строк, Compose 1000, Message 998: загрузка, выбор, bulk, undo, шиты в одном компоненте. Любая фича Gmail-diff раздует дальше. Сначала `useMailList` / `useMailSelection`.
P2. Bulk без undo. `runBulk` (`NativeMailInboxScreen.tsx:659`) нигде не делает `setUndo`; undo есть только у свайпа (`:566`, `:583`). Массовый архив нельзя отменить, Gmail умеет.
P3. Bulk по цепочкам N+1 и последовательно: `getMailConversation` на каждую выбранную цепочку (`:669`), неполная цепочка роняет всё действие целиком. Нужны лимит параллелизма и поитемённый результат либо серверный bulk по цепочкам.
P4. Два контура отправки: `sendQuickReply` и `send()` в compose дублируют идемпотентность и проверку «Отправленных». Transfer между ними — in-memory Map, живёт только сессию.
P5. Unread-дельты в четырёх местах (inbox, message, conversation, уведомления) без единого источника; компенсация есть, теста инварианта нет. Частичная bulk-ошибка может рассинхронить бейдж навигации.
P6. Entity snapshot хранит полный detail с `body_html` на каждое открытое письмо (`writeNativeEntitySnapshot`), а шардирования и эвикции у mail scope нет — в отличие от address-book и equipment. Offline покрывает только посещённое, рост не ограничен. Решить лимит до расширения offline.
P7. Центр уведомлений дублирует mail-логику чтения (`markMailMessageRead` + свой persist + publish в `NativeNotificationCenterScreen.tsx`). Смена API чтения чинится в двух модулях.

## Gmail-diff от 2026-09-25

Сверено с кодом `mobile-hub`: в mail API и клиенте нет star/flag, snooze, отложенной отправки, mute, автоответа, блокировки отправителя, отмены отправки и истории поиска (`mailApi.ts`, `mailConfigApi.ts`, `src/mail`). Внешние картинки уже заблокированы по умолчанию (`NativeMailHtmlBody.tsx:63`, плейсхолдер «Внешнее изображение скрыто») — как в Gmail, не трогать.

Делаем в этом контуре, backend не нужен:

- Шапка получателей из finding 16: «Кому: мне / имя +N», Bcc только свои.
- Настройка жестов: выбор действия на свайп влево/вправо (архив, удалить, прочитано). Сейчас жест зашит в `nativeMailModel.ts:12`.
- Недавние запросы в поиске: локальная история, тап подставляет запрос. Сейчас истории нет.
- Операторы в строке поиска: `от:`, `кому:`, `тема:`, `с файлами` маппятся на существующие фильтры. Сейчас только свободный текст плюс отдельная advanced-форма.
- Очистка корзины: «Удалить всё навсегда» через существующий bulk delete permanent с тем же подтверждением. Сейчас только поштучно через выбор.
- Спам: отдельное действие не нужно, покрывается перемещением в Junk — проверить, что Junk видна в move sheet.

Не делаем: нужен backend или хранилище на сервере. Звёзды, snooze, отложенная отправка, отмена отправки, mute переписки, автоответ, блокировка отправителя, категории и вкладки Gmail, конфиденциальный режим, умные ответы. Это не отказ навсегда, а отдельный контур с API-контрактом.

### Цели клиента

Замерять на одном Android, одна и та же папка, 50 писем, светлая и тёмная тема. Кэш — попадание в `mail-inbox` snapshot. Сеть — офисный Wi-Fi и отдельно холодный Exchange. Не переносить один прогон на production.

| ID | Метрика | Цель | Неуспех |
|---|---|---|---|
| M1 | Время до первой строки при попадании в снимок | ≤ 300 мс от фокуса экрана | Список мигает пустым до чтения снимка |
| M2 | Время до первой строки при тёплом API | ≤ 1.2 с, если серверный list P95 warm ≤ 0.8 с | Скелет дольше серверного SLO без причины на клиенте |

## Оптимизации

Сначала замер M1–M7, потом одна правка. Не добавлять Redis, новый сервис и кэш HTML.

### Делать

1. Не очищать список до проверки снимка. Сейчас при `reset && !cached` строки обнуляются, и только потом читается snapshot (`NativeMailInboxScreen.tsx:328`). Это прямой кандидат на M1. Для смены папки чужие строки не показывать: очищать только после промаха снимка.
2. Первую страницу не раздувать без замера. `PAGE_SIZE=50` против серверного bootstrap 20. Если M2 упирается в Exchange, первая страница 20–25, дальше 50. Не менять размер, если узкое место — клиентский рендер.
3. Сохранить два инварианта: список раньше метаданных; refresh не перерисовывает смонтированные строки.
4. Тему письма рисовать до WebView. WebView остаётся `incognito`, `cacheEnabled={false}`: это граница безопасности, не тормоз, который надо снимать.
5. `extraData={selected}` перерисовывает видимые строки при выборе. Трогать только если M4 покажет лишние кадры. `getItemLayout` не добавлять: после снятия потолка шрифта высота строки перестанет быть постоянной.
6. Свайп и undo остаются оптимистичными. Архив не должен ждать ответ Exchange, чтобы сдвинуть строку. Ошибка возвращает строку и оставляет undo.
7. Поиск не учащать. 320 мс оставить, пока M7 не покажет, что пользователь ждёт раньше, а Exchange выдерживает.
8. Снимок писать после показа списка, не внутри транзакции UI. Сейчас запись уже не блокирует `setItems`, это сохранить. Тела с HTML уже хранятся в entity snapshot — новых не добавлять, пока не решён лимит и эвикция по P6.

### Не делать

- Кэш и cookies WebView для HTML письма.
- Фиксированную высоту строки ради `getItemLayout`.
- Отдельный брокер, Redis или фоновый воркер ради списка.
- Преждевременный перевод первой страницы на 20 без M2.
- Оптимизацию цепочек как режим по умолчанию: выбран режим писем.

## План работ

1. Замер. Снять M1–M7 на текущем APK. Записать устройство, тему, cold/warm, cache hit/miss. Без этого фазы 2–3 не объявлять быстрее.
2. Список. Finding 1, 2, 3, 5, 7. Плюс порядок «снимок, потом очистка» из оптимизации 1. Лимит и эвикция snapshot по P6. Режим по умолчанию не менять.
3. Жест и выбор. Вправо прочитано, влево архив. В корзине влево — удалить навсегда только после кнопки «Удалить навсегда». Undo гаснет сам через 5 с и не перекрывает последнюю строку, bulk тоже отменяется (P2). Bulk по цепочкам без N+1, с поитемённым результатом (P3). Тест инварианта unread (P5). Настройка действий свайпа в настройках вида. Очистка корзины одной кнопкой через bulk delete permanent. Finding 8, 13.
4. Читатель. Одна нижняя зона, архив без «Ещё», одна иконка важности, красная точка только при непрочитанных > 0. Тема до WebView. Шапка получателей из finding 16. Контракт отправки один на оба контура, дубль не объединять (P4). Finding 4, 6, 11, 15, 16.
5. Поиск и шиты. Пустой поиск называет запрос. Дата — календарь. Safe area у шитов. Недавние запросы и операторы `от:/кому:/тема:/с файлами`. Finding 9, 10, 12.
6. Папки и настройки. «Новая папка в архиве». Сырой `auth_mode` не показывать пользователю. Junk видна в move sheet. Чтение почты — один слой с уведомлениями (P7). Finding 14.

Вне объёма: категории Gmail, snooze, отложенная отправка, отмена отправки, звёзды, mute, автоответ, блокировка отправителя, конфиденциальный режим, визуальный клон, цепочки по умолчанию, смена серверных SLO.
