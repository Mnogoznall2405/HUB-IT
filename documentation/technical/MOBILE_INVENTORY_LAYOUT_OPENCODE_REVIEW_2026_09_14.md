# Инвентарь: компоновка и совместимость OpenCode

## Изменение компоновки по скриншоту

В `mobile-hub/src/screens/database/NativeDatabaseScreen.tsx` счётчик больше не конкурирует за ширину с тремя действиями. Поиск отделён от ряда «Добавить / Выбрать / Ещё» на 10 dp. Текстовые действия распределяют свободную ширину, могут переносить подписи и увеличивать высоту, минимальная высота — 44 dp. «Ещё» расположен последним, дополнительные действия раскрываются отдельным рядом. Счётчик и переключатель истории «Недавние» объединены ниже. Сам горизонтальный список недавних карточек появляется только при раскрытии.

Вкладки оборудования, расходников и актов переходят в вертикальную компоновку, если доступная ширина с учётом fontScale меньше 300 dp. Убрано ограничение числа строк названий вкладок и масштабирование кнопки выбора базы при нажатии. Для основных действий добавлен отклик прозрачностью.

Изменён только этот экран; существующие изменения в его Git diff сохранены. Нижняя навигация в этом этапе не менялась: код уже содержит скруглённый индикатор, а причину квадратного выделения на присланном скриншоте без устройства воспроизвести не удалось.

## OpenCode: исходная проверка поддержки и пробелов

Мобильный клиент имеет ИИ-диалоги, панель `ChatOpenCodePanel`, просмотр файлов/изменений и отправку разрешений once/session. Пути и тела запросов в `src/api/chatApi.ts` совпадают с `WEB-itinvent/backend/api/v1/chat/ai_sandbox.py` и схемами `ai_sandbox/schemas.py`. Обычные сообщения обновляются через `chat.message.created/updated`; доставленные вложения можно сохранять в «Мои файлы» через меню вложения.

Нельзя считать весь сценарий готовым:

1. `ChatOpenCodePanel.tsx:49`: загрузка выполняется при открытии/смене диалога и после действия; подписки или периодического обновления нет. Новые разрешения и результаты при открытой панели не появятся автоматически.
2. `ChatOpenCodePanel.tsx:73` и `:89`: успешный HTTP 202 показывается как уже прикреплённый файл/архив. Сервер возвращает `SandboxJobAccepted`, то есть доставку ещё нужно дождаться.
3. В мобильном API и экране диалога отсутствует чтение нового `/chat/ai/conversations/{conversation_id}/access`. Сервер защищает отправку, но мобильный композер заранее не объясняет отзыв назначения. Актуальные правила: активный администратор либо отдельное назначение агента; старое право `chat.ai.sandbox` недостаточно.
4. Асинхронная загрузка панели не защищена от устаревшего ответа при смене диалога. `busyKey` блокирует только одно совпадающее действие: параллельные действия могут перезаписывать индикатор занятости.
5. В панели нет выбора исходных файлов из «Моих файлов» и прямого сохранения результатов workspace в хранилище, которые есть в web-сценарии. Уже доставленное вложение можно сохранить через обычное меню сообщения.

Это read-only проверка OpenCode; код чата и сервера не менялся. Приоритет доработки: обновление панели и защита контекста, корректный статус асинхронной доставки, отражение доступа в композере, затем интеграция выбора файлов.

## OpenCode: исправления после согласования

Замечания 1–4 выше устранены в мобильном коде:

- `ChatOpenCodePanel.tsx`: обновление состояния каждые 5 секунд на открытом экране, кнопка ручного обновления, пауза в фоне и офлайн, обновление при возвращении. Компонент состояния разделён по пользователю, диалогу и offline-контексту. Ответы завершённых запросов не переносятся в другой диалог. Операции сериализованы локальным ref-lock, на время операции отключены все действия панели.
- Ответы HTTP 202 больше не обозначают завершение доставки. Панель сообщает, что доставка/подготовка запрошена; для файлов показывает серверные состояния pending, attached и unavailable.
- `useAiAgentAccess.ts` и `chatApi.ts`: существующий owner-scoped API `GET /chat/ai/conversations/{id}/access`, проверка при открытии/возвращении и каждые 15 секунд в активном приложении. Устаревший ответ другого пользователя/диалога игнорируется. Ошибка проверки блокирует действия до следующей успешной проверки.
- `NativeChatThreadScreen.tsx`: состояние доступа используется в композере и существующей проверке актуальности отправки. При отзыве показано объяснение; история остаётся доступной, текст черновика не удаляется. Сервер продолжает независимо проверять доступ при каждом действии. Обычные не-ИИ диалоги не запрашивают этот API. Без сети отправка ИИ-агенту недоступна.

Проверено: 77 наборов / 569 тестов области chat/components/chat/screens/chat — PASS; отдельно 27 тестов access/API — PASS (4 теста hook входят также в общую регрессию). TypeScript — PASS; Android-export — PASS (`mobile-hub/artifacts/opencode-android-export-20260914`). Тесты включают обновление разрешений, фон/возврат, offline, смену диалога с незавершённым запросом/действием, сериализацию действий, отзыв/возврат доступа и сохранение введённого текста.

Замечание 5 — выбор файлов из «Моих файлов» непосредственно в панели workspace — остаётся отдельной возможностью; обычное сохранение доставленного вложения через меню сообщения уже существует. В этом этапе не запускались задания модели, не менялся backend и не публиковался APK. Установка, авторизованный сценарий с Linux worker и жесты на Android остаются непроверенными.
