# Администрирование файлов и выдача доступа

Статус на 2026-11-05: код находится в действующем frontend/backend; при публикации
[истории ONLYOFFICE](ONLYOFFICE_DOCUMENT_HISTORY.md) baseline интерфейса подтверждён по 473 ресурсам,
а работающие API содержат маршруты админки. Матрица прав проверена локально;
полный пользовательский проход с авторизованной production-учётной записью не выполнялся.

## Правила

| Объект | Кто меняет прямые приглашения и публичную ссылку |
| --- | --- |
| Личный файл | Владелец и активный администратор платформы |
| Файл общей папки | Загрузивший/создавший файл, пока он состоит в общей папке, и администратор |
| Старый файл общей папки без `uploaded_by_user_id` | Администратор; автор не вычисляется по последнему сохранению |
| Публичная ссылка на подпапку общей папки | Администратор |

Роль библиотеки `manage` сама по себе больше не разрешает делиться чужим файлом.
Её существующие права на содержимое и корзину сохраняются. Состав общей папки по-прежнему
меняется через настройки библиотеки с правом `my_files.libraries.manage`.
Прямые приглашения к личным папкам доступны их владельцу и администратору;
для подпапок библиотеки используется существующий состав библиотеки.

Приглашение к отдельному файлу библиотеки не открывает остальные файлы или саму библиотеку.
Фактическая роль — максимальная из прямой и унаследованной. Отзыв прямого приглашения
не отменяет роль библиотеки/родительской папки; диалог сообщает об этом отдельно.
Существующие приглашения и публичные ссылки автоматически не отзываются.

Администратор открывает, редактирует, скачивает, переименовывает, выдаёт доступ,
просматривает журнал, перемещает файл в корзину и восстанавливает его от своей учётной записи.
Владелец/автор не подменяется. Гранты скачивания и callback сохранения повторно проверяют
доступ; снятие административной роли блокирует дальнейшее чужое редактирование.
Проверки антивируса, срока хранения, готовности и корзины сохраняются.
Окончательного удаления в новом интерфейсе нет.

## Интерфейс и API

Администрирование → «Мой диск» → «Все файлы». В статистике пользователя есть
«Открыть файлы». Поиск охватывает имя файла, пользователя, автора загрузки и папку;
есть фильтры личных/общих файлов и корзины, постраничная загрузка.
Делегированное право просмотра статистики не открывает вкладку всех файлов.

- `GET /api/v1/my-files/admin/files`: `q`, `owner_user_id`, `scope=all|personal|library`,
  `state=active|trash|all`, `limit=1..200`, `offset`. Только администратор; роль и активность
  дополнительно проверяются в БД.
- `GET /api/v1/my-files/admin/files/{id}`: актуальная строка после действия.
- Остальные операции используют обычные существующие endpoints файлов и ONLYOFFICE.
- `MyFileResponse.can_manage_access` и `office/config.can_manage_access` — серверная возможность
  выдачи доступа. Клиент дополнительно учитывает `my_files.share`; отсутствие поля закрывает действие.
- Список прямых приглашений дополнен фактическим `owner`, `owner_kind`,
  `inherited_access`, `library_name`. Сохраняются только прямые приглашения.

После операции обновляется строка файла. Переименование убирает её из результатов,
если новое имя больше не соответствует поиску. Ошибка загрузки не отображается как пустой список.
Смена аккаунта отключает старые запросы, диалоги, копирование ссылки и выдачу скачивания.

Основные файлы: `services/my_files_admin_service.py`, `my_files_service.py`,
`my_files_collab_service.py`, `api/v1/my_files.py`, `my_files_office.py`, `models/my_files.py`;
frontend `api/myFilesAdmin.js`, `pages/account/admin/MyFilesAdminTab.jsx`,
`MyFilesAdminBrowser.jsx`, `pages/MyFiles.jsx`, `components/myFiles/MyFilesCollaboratorsDialog.jsx`,
`pages/myFiles/useMyFilesShares.js`, `useMyFilesDownload.js`.

## Журнал ячеек ONLYOFFICE

В штатной истории таблицы видны версии/ревизии, автор и время, изменения автора подсвечиваются:
[руководство ONLYOFFICE](https://helpcenter.onlyoffice.com/docs/userguides/spreadsheet_editor/VersionHistory.aspx).
Для этого интегратор должен сохранять данные правок `history` и архив `changesurl`,
обрабатывать `onRequestHistory`/`onRequestHistoryData` и выдавать `refreshHistory`/`setHistoryData`:
[контракт интеграции](https://api.onlyoffice.com/docs/docs-api/get-started/how-it-works/document-history/).

На этапе админки сохранялись файлы версий и события сохранения/выдачи доступа.
Следующим этапом локально реализованы сохранение архивов правок и штатный просмотр истории:
[ONLYOFFICE_DOCUMENT_HISTORY.md](ONLYOFFICE_DOCUMENT_HISTORY.md), опубликовано 2026-11-05 в 11:26.
По одному XLSX и последнему сохранявшему нельзя достоверно восстановить авторство каждой старой правки.
