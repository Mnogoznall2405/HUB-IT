## 4. Найденные узкие места и аномалии

1. **`menu_open_last`: longtask ~600 мс в ОБЕИХ версиях** (669/736 base → 596/624 after, −11/−15%). Открытие контекстного меню на последней строке большого списка сопровождается длинной задачей (позиционирование MUI Menu + мутации списка). Видимая задержка при этом ~90 мс — пользовательски незаметно, но это общий предсуществующий хот-спот. Регрессии нет — after чуть лучше.
2. **`table_500` p95 +14.6%** (1584→1816, n=10): первичная оценка ставила «реальное замедление на границе порога». Дозамер n=20 на свежем сиде опроверг: first_row p50 −0.3%, p95 +7.0%, heap p50 −45% (510→281 МБ). Регрессии нет; +1 API-запрос (13→14) — лишний запрос дерева библиотек, осмысленная цена нового сайдбара.
3. **p95-выбросы** в `nav_back` (616), `details_open_1000` (1016), `view_toggle_back` (953), `menu_open_last` (150): одиночные максимумы на 10 прогонов, p50 при этом в пределах ±10%. Трактовались как GC/сетевой шум — для трёх ключевых сценариев подтверждено дозамером (см. §4.1).
4. **`sidebar_expand` +20 мс p50**: осмысленная цена — после PR #18 в сайдбаре строится дерево библиотек/папок. Цель 100 мс выдержана.
5. **`open_route heap_mb` +76% p50 (21.6→38.1) при p95 +3.6%** и **`table_1000 heap_mb` −69%**: метрики `performance.memory` скачут от GC-тайминга; направления противоречат друг другу → вывод о росте/экономии памяти сделать нельзя. Утечек по churn-тесту нет.
6. **Скролл ~35–40 FPS вместо 60**: прогрессивный рендер + 1000 строк в DOM; `content-visibility` смягчает, но не виртуализирует. Одинаково в обеих версиях — кандидат на будущую виртуализацию списка (вне объёма PR #18).
7. **`nav_rapid`**: метрика settled=0 в обеих версиях (последний переход обнуляет окно) — неинформативна, исключена из выводов.

### 4.1 Дозамер p95-аномалий (n=20, свежий сид)

Три сценария с p95-превышениями в основном прогоне (`nav_back` +93%, `view_toggle_back` +21%, `table_500` +15%) были повторно измерены на **20 прогонах** после пересидирования обоих backend (тот же объём данных, поднятые тест-лимиты). Результаты — шум подтверждён измерением, не предположением:

| Сценарий | Метрика | Baseline p50/p95 (n=20) | After p50/p95 (n=20) | Δ p95 | Вывод |
|---|---|---|---|---|---|
| `nav_back` | settled_dom | 152 / 168 | 153 / 164 | **−2.4%** | выброс 616 в основном прогоне — шум |
| `nav_back` | longtask_ms | 144 / 174 | 151 / 171 | −1.7% | паритет |
| `nav_back` | api_requests | 3 / 3 | 3 / 3 | 0 | идентично |
| `view_toggle_back` | settled_dom | 792 / 882 | 786 / 837 | **−5.1%** | выброс 953 — шум |
| `view_toggle_back` | first_dom | 36 / 54 | 37 / 48 | −11.1% | паритет |
| `table_500` | first_row_ms | 1533 / 1787 | 1529 / 1912 | +7.0% | в пределах шума (p50 −0.3%) |
| `table_500` | heap_mb | 510 / 864 | 281 / 481 | **−45%** | after экономнее |
| `table_500` | api_requests | 13 / 13 | 14 / 14 | +1 | лишний запрос дерева библиотек — осмысленная цена сайдбара |

**Итог дозамера:** регрессий по этим трём сценариям нет. Замечание остаётся только по `+1` API-запросу при заходе в каталог 500 (новый сайдбар грузит дерево) — детерминированная цена функционала, не деградация.

## 5. Оптимизации по результатам аудита

Подтверждённых регрессий, требующих правки кода, не выявлено — в код продукта изменения не вносились. Исправления коснулись только харнесса: кросс-версионные селекторы (правый клик вместо ⋮ в baseline), гейт `PERF_ONLY` для точечных дозамеров, дедупликация CSV по (scenario,metric,run) с сохранением последнего значения, фильтр сентинела `-1`, fallback на `document.scrollingElement` для скролла, вкладка «Доступ» в диалоге библиотеки. Ранее зафиксированный агрегат `menu_open_kebab` ~973 мс оказался артефактом последовательности харнесса — честный дозамер дал 84/90 мс.

## 6. Ограничения

- NVDA на машине не установлен; Narrator не автоматизируется — скринридер-проверки в аудит не входят (см. a11y-раздел в `MY_FILES_COMPACT_UX_REVIEW.md`).
- Heap-метрики — один снапшот на замер, GC-шум; `memory_nav_churn` — по 1 прогону.
- Бэкенды изолированные SQLite + сид-данные; продакшен SQL Server и сеть не моделировались.
- Тест 5000 файлов не выполнялся: API листинга без пагинации, сид на 1610 файлов упирался в лимиты загрузки; методически 1000 строк без виртуализации уже показывает потолок.
- 2 Chrome-трейса сохранены в `traces/` (по одному на сторону).

## 7. Итог

1. **Регрессий производительности, блокирующих merge, нет.** Все дельты p50 в пределах ±11%; p95-превышения `nav_back`/`view_toggle_back`/`table_500` проверены повторным измерением n=20 на свежем сиде — подтверждены как шум (§4.1), единственное детерминированное изменение — +1 API-запрос дерева библиотек в сайдбаре.
2. **Улучшения:** навигация в общую папку −16/−40%, раскрытие дерева −27/−36%, поиск p95 −48%, меню −10%, скролл +7% FPS.
3. **Узкие места (не регрессии, общие для обеих версий):** longtask ~600 мс при меню на последней строке; скролл ~35–40 FPS без виртуализации; settled-перерисовка списка 500–950 мс при смене вида.
4. **Утечек памяти не выявлено** в меру имеющихся замеров.
5. **PR #18 к merge готов** по результатам производительности и приёмки. HEAD ветки: `9879be04` (на коммит новее запрошенного `338912d9` — фикс container-aware сетки колонки имени, проверен теми же e2e-спеками).
