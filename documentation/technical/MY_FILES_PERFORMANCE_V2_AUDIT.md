# My Files — Performance V2: аудит и подтверждённые причины

Стенд: два изолированных backend (`:18011` baseline-сборка `26cfd4ef`, `:18012` HEAD `perf/my-files-v2`), превью `:5181`/`:5182`, Chrome, `e2e/perf/my-files-perf.mjs`, одинаковые сиды (f10/f100/f500/f1000, библиотеки A/B с 150 папками и цепью 13, nav-цепочка, маркеры).

## Подтверждённые причины задержек (baseline, n=10, p50)

| Сценарий | Метрика | Причина (доказательство) |
|---|---|---|
| Открытие f1000 | first_row 1730 мс, longtask 1151 мс | React commit ~200 строк + layout/paint ~9800 DOM-узлов; «порционный рендер» 200/шаг — не виртуализация |
| Скролл f1000 | fps 42.5, worst 33 мс | Все 1000 строк смонтированы: style/layout обходится по полному дереву при любом изменении |
| Сортировка | longtask 2112 мс | Пересортировка + перерендер всех смонтированных строк |
| Select-all | longtask 641 мс | setSelected на 1000 строках → обновление каждой строки |
| details_open_1000 | longtask 1130 мс | Сдвиг ширины контента → container-query пересчёт по 9800 узлам |
| menu_open_first | longtask 588 мс | MUI Modal + scroll-lock (рефлоу документа) + ререндер страницы |
| view_toggle | 528/770 мс | Полный unmount/mount разных деревьев компонентов |
| search_type | settled 762 мс, 31 commit, до 6 API | Фильтрация+сортировка 1000 элементов на каждый keystroke |
| Навигация | 3 API-запроса на переход | `listFiles` + `getQuota` + `listFolders` (полное дерево) каждый раз; библиотеки грузились повторно до фикса |
| Строки | — | `Intl.DateTimeFormat` создавался на строку; `entryAccess` пересчитывал права на каждую строку |

## Что было сделано (HEAD)

1. Настоящая window-виртуализация списка и сетки (`useWindowVirtualRows`, квант окна 16, overscan 8, фиксированные высоты).
2. SWR-кэш листингов в памяти страницы (TTL 20 с, ≤30 ключей, инвалидация на мутациях, без персистентного хранилища).
3. Debounced-поиск (250 мс), `accessOfEntry` memo, общий `Intl.DateTimeFormat`, `disableScrollLock`, memo-флаги выделения, стабильный `EMPTY_ARRAY`.
4. Харнесс обновлён под виртуализацию (скролл к концу, spacer-проверки, PERF_TABLE_SIZES).

## Остаточные ограничения

- Холодная навигация дороже на ~120–170 мс p50 (settled 195→315 мс): три виртуализатора измеряют окно на смену `itemCount`, SWR добавляет второй apply — commits 7→15. Платим за −84% DOM и −62% first_row на больших папках.
- Скролл в виртуализированном списке платит remount строк на границах окна — на патологическом прогоне (+300px/кадр) fps ~38.7 против 42.5 у «всё смонтировано», worst_frame 33→67 мс. При реальном скролле колёсиком стоимость кадра ниже за счёт малого DOM.
- Backend не менялся: `preview_path.is_file()` на строку, агрегаты квоты, отсутствие ETag/пагинации — P2/P3, см. план.
