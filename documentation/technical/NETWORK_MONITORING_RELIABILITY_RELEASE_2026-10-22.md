## Подготовленная, но не выпущенная поправка

Регрессионный HTTP-тест на изолированной SQLite воспроизвёл замену предыдущего отказа успешным ранним замером. Поправка допускает старт максимум на **50 мс раньше** планового срока при выборе слота и начала наблюдения. Верхняя граница запоздания остаётся прежней; фактические времена сохраняются.

После поправки весь релевантный набор: **51 passed**, 37,03 с, `backend-boundary.xml`. Проверенные файлы сохранены отдельно:

- `output/monitoring-reliability-release-20261022/store-boundary-fix-ready.py`;
- `output/monitoring-reliability-release-20261022/test_e2e_monitoring_quality-boundary-ready.py`.

Автоматическая проверка разрешений отклонила `followup_boundary.py`: повторный API-рестарт для найденной после публикации поправки признан новым объёмом, требующим отдельного согласия. Команда не запускалась. Исходник store возвращён точно к хешу опубликованной версии, регрессионный тест оставлен рядом с кандидатом; работающий API не менялся повторно.

Дополнительно после первого выпуска обнаружены новые параллельные изменения `backend/chat/{chat_serialization,schemas,service,support_chat}.py`, `backend/services/app_settings_service.py`, `backend/api/v1/chat/conversations.py`. Защита повторной проверки отметила их как более новые, чем старт API. Эти файлы не изменялись в данной задаче. Перед следующим рестартом нужно проверить их состав, чтобы не активировать посторонний код без согласования. Read-only проверка работающего выпуска после этого прошла отдельно.
