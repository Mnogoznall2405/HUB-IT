# Совместное редактирование Word/Excel в «Моих файлах» (ONLYOFFICE)

Статус на 2026-11-02: код написан и проверен локально; **на проде не включено** (`ONLYOFFICE_ENABLED=0`,
миграция не применена, IIS-правило не опубликовано). Сквозной сценарий с настоящим Document Server не проверен.

## Как устроено

- Document Server: ВМ `TMN-SRV-AI-01` (10.103.0.11), Podman Quadlet `/etc/containers/systemd/onlyoffice.container`,
  сервис `onlyoffice.service`, порт `10.103.0.11:8080`, данные `/srv/onlyoffice`, JWT включён
  (секрет в root-only `/etc/onlyoffice/ds.env`).
- Браузер открывает редактор из того же origin: IIS правило `ONLYOFFICE Reverse Proxy`
  (`WEB-itinvent/frontend/public/web.config`) проксирует `/onlyoffice/*` на Document Server вместе с WebSocket.
- Бэкенд: `api/v1/my_files_office.py`, `services/onlyoffice_service.py` (JWT, конфиг редактора),
  `services/my_files_collab_service.py` (доступ, версии, сохранение).
- Файл редактируют владелец и выбранные пользователи портала (`my_file_collaborators`). Публичные ссылки остаются
  только на чтение.
- Поддерживаются `.docx` и `.xlsx`. Старые `.doc`/`.xls` не открываются.

## Версии

Первое сохранение сессии редактирования переносит прежнее содержимое в `my_file_versions` (ссылка на блоб
переходит от файла к версии, счётчики не меняются). Автосохранения и закрытие той же сессии заменяют текущее
содержимое без новых версий. Хранится `ONLYOFFICE_MAX_VERSIONS` (20) версий; история входит в квоту владельца.
Окончательное удаление файла и истечение срока освобождают версии (`MyFilesService._release_file_collab_locked`).
Вернуть версию можно из меню файла; текущее содержимое при этом становится новой версией.

`document.key` зависит от файла и числа версий и меняется только после сохранения. Принудительное сохранение
(`forcesave`) выключено: его callback `status 6` менял бы ключ посреди живой сессии, и новые участники попадали бы
в отдельную копию. Callback приходит при закрытии сессии (`status 2`); после возврата версии открытые сессии получают
устаревший ключ, их сохранения игнорируются (в логе `office.save_stale`).

Токен `document.url` живёт 10 минут (Document Server забирает файл при открытии), токен `callbackUrl` — 30 дней
(`ONLYOFFICE_TOKEN_TTL_SEC`); тело callback дополнительно подписано JWT Document Server.

CSP в `web.config` пока `Report-Only`: при переводе в `enforce` редактору нужны разрешения для `/onlyoffice`
(inline/eval-скрипты и фреймы того же origin). `X-Frame-Options: SAMEORIGIN` его не блокирует.

## Что нужно для включения (по порядку, каждый шаг только по явному решению)

1. Миграция: `alembic -x url=<url> upgrade 20261102_0156` (создаёт обе таблицы «если нет»). До неё код не падает:
   `_collab_tables_present` держит квоту и очистку в прежнем виде.
2. IIS: опубликовать `web.config` и в ARR разрешить серверные переменные `HTTP_X_FORWARDED_HOST`,
   `HTTP_X_FORWARDED_PROTO`, `HTTP_X_REAL_IP`, `HTTP_SEC_WEBSOCKET_EXTENSIONS` (как для LiveKit и чата).
3. `.env` HUB: `ONLYOFFICE_ENABLED=1`, `ONLYOFFICE_JWT_SECRET` (значение из `/etc/onlyoffice/ds.env`, передать без вывода в чат),
   `ONLYOFFICE_INTERNAL_URL=http://10.103.0.11:8080`, `ONLYOFFICE_APP_BASE_URL`. Затем штатный `restart-backend.ps1`.
4. Сеть Document Server → HUB: проверено 2026-11-02 с ВМ (только чтение). `hubit.zsgp.ru` резолвится на ВМ в
   10.103.0.217, HTTPS с проверкой сертификата проходит (`ssl_verify=0`), то есть `ONLYOFFICE_APP_BASE_URL=https://hubit.zsgp.ru`
   подходит без `AddHost` и без отключения проверки TLS. Запрос на IP `https://10.103.0.217` не годится: канонический
   редирект IIS отвечает 307. Боевой backend на момент проверки отвечал 404 на `/api/v1/my-files/office/status`
   (код ещё не загружен процессами).
5. Фронтенд: сборка и публикация штатным процессом IIS.

## Откат

Выставить `ONLYOFFICE_ENABLED=0` и перезапустить backend — действия в меню пропадают, данные остаются.
Миграцию откатывает `downgrade`, но он удаляет историю версий и список соавторов (блобы версий тогда останутся
без владельца-ссылки: перед откатом освободить версии или принять потерю места).

## Остаточные риски

- Ответ на callback отправляется после сохранения (антивирус, хеш, публикация в хранилище); большие файлы
  могут превысить таймаут Document Server и вызвать повтор. Повтор безопасен: содержимое не меняется, версия не дублируется.
- ВМ имеет 2 CPU и 3,8 ГБ RAM; для рабочей нагрузки нужно 4 CPU и 8 ГБ.
- Редактор в Desktop (WebView2) и mobile-hub не проверялся.
