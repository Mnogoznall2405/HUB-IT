## Поведение

`DesktopWindowManager.OpenSecondaryRoute` уже переиспользует второе окно и отправляет
`navigation.open` в React Router. `pages/MyFilesEditor.jsx` передаёт маршрут в
`components/myFiles/MyFilesEditorWorkspace.jsx`: новый ID добавляет вкладку, повторный активирует
существующую. У каждого файла собственные `MyFilesEditorShell` и SDK iframe.
Переключение сохраняет размеры, соединение, историю и неотправленные правки редактора.
Неактивные панели скрыты и `inert`; диалоги управления не перекрывают другой документ.
Смена аккаунта удаляет прежний workspace; поздние ответы не создают редактор старого пользователя.

Крестик вкладки сначала показывает документ, затем вызывает штатный `requestClose`.
Если открыта история, подтверждение берётся у живого документа. После закрытия выбирается
соседняя вкладка; последняя возвращает к «Моим файлам» либо закрывает созданную браузером вкладку.
Клавиатура: стрелки переключают вкладки, Delete закрывает выбранную с проверкой правок.
Обычный браузер по-прежнему открывает файлы в отдельных вкладках браузера.

`SecondaryHubWindow.OnClosing` проверяет страницу только на доверенном origin и строгом
маршруте `/my-files/edit/{id}`. Отправляется отменяемое событие `hub:before-close`, на которое
подписаны все живые сессии. При неотправленных правках требуется подтверждение с ответом
«Нет» по умолчанию; при ошибке/таймауте окно остаётся открытым. Смена страницы во время
проверки отменяет устаревшее решение. Обычный `beforeunload` здесь не вызывается:
его другие обработчики HUB могут, например, завершить звонок.
Для этой защиты необходима новая сборка Desktop вместе с frontend.

## Где история и что записывается

Кнопка **«История»** рядом со вкладками открывает историю выбранного файла в области редактора.
Сохраняется штатный пункт ONLYOFFICE **«Файл → История версий»** / **«Совместная работа → История версий»**.
Живой редактор остаётся открытым, просмотр версии не уничтожает текущие правки.

Существующий backend автоматически принимает сохранённый файл, авторов и архив изменений
callback; пользовательского переключателя этой записи нет. Настройка Word «Записывать исправления»
управляет согласованием правок и не требуется для истории HUB.
Новая версия появляется после завершения общей сессии: документ закрыли все участники,
Document Server сформировал результат, HUB успешно принял callback. Оставленная открытой
фоновая вкладка остаётся участником сессии. Это история сохранённых версий, а не журнал каждого
нажатия в текущей сессии. Подсветка конкретных правок зависит от сохранённого архива;
отсутствующие данные прежних версий восстановить из одного файла нельзя.
Политика хранения не меняется: `ONLYOFFICE_MAX_VERSIONS`, default 20, существующие квоты/сроки.
Не добавлены принудительный review, новая БД, миграция, forcesave или бессрочный аудит.
Серверный контракт и ограничения: [ONLYOFFICE_DOCUMENT_HISTORY.md](ONLYOFFICE_DOCUMENT_HISTORY.md).
