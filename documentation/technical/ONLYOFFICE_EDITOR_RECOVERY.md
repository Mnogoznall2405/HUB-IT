## Контракт с HUB

Локальное дополнение 2026-11-06 (публикация отдельно): исправлены два воспроизведённых
сбоя вызова `refreshFile`. Если SDK выбрасывает исключение, HUB возвращает прежнюю
конфигурацию сессии и повторяет ту же версию с обычной задержкой; счётчик попыток
сбрасывается только после успешного вызова. iframe и текст не пересоздаются.
Если SDK сообщает критическую ошибку синхронно внутри `refreshFile`, статус ошибки
сохраняется и не затирается последующим «Редактор готов» или общей обработкой исключения.
До исправления оба новых E2E падали; после прошли 29 сценариев recovery/workspace.
Артефакты и границы: `output/onlyoffice-reliability-20261106/README.md`.

- Восстановлением WebSocket занимается штатный SDK ONLYOFFICE. HUB сохраняет существующий iframe при
  `offline`/`online` и показывает состояние сети, не создавая новый редактор автоматически.
- Когда SDK присылает `onRequestRefreshFile`, запрашивается существующий `GET /my-files/{id}/office/config`.
  Через него повторно проверяются права HUB и получается полный подписанный конфиг текущей версии.
  Свежий конфиг передаётся целиком в `refreshFile`, сохраняя подпись, имя файла и callback.
- Если ключ версии ещё прежний, HUB повторяет запрос с задержкой: завершение записи файла может отставать
  от переподключения редактора. Ключ не меняется на клиенте, `forcesave` не включается.
- При сетевой ошибке, HTTP 429 или 5xx используются одиночные запросы с экспоненциальной задержкой
  и разбросом (до 30 секунд). Числовой `Retry-After` учитывается до 300 секунд. После возврата сети или
  видимой вкладки ожидающий запрос можно продолжить сразу. Во время одного запроса второй не запускается.
- Неотправленные правки приостанавливают обновление версии. Если пользователь начал писать во время
  запроса, его ответ тоже не заменяет документ до подтверждения передачи правок SDK.
- 401/403/404/410 останавливают восстановление. Смена пользователя, типа документа, адреса редактора
  или неполный подписанный конфиг также останавливают обновление. Редактирование блокируется штатным
  `denyEditingRights`, содержимое окна сохраняется для действий пользователя.
- При понижении роли `edit`/`comment` вызывается `denyEditingRights` и требуется явное переоткрытие.
  В установленном SDK `refreshFile` сохраняет первоначальные параметры режима и permissions, поэтому
  использовать его как смену роли нельзя даже при новом ключе документа.
- Запросы отменяются и обработчики отключаются при уходе со страницы, смене файла или учётной записи.
  Поздний ответ предыдущей сессии не применяется к новому редактору.

## Статусы и закрытие

`onAppReady` означает готовность оболочки: закрывается перекрывающая загрузка, чтобы пользователь мог
ответить на запрос пароля или другое действие внутри SDK. Готовность документа отслеживается отдельно
через `onDocumentReady`. Долгая загрузка даёт предупреждение и возможность явного переоткрытия.
После `refreshFile` повторный `onDocumentReady` не требуется, поскольку документ не перезагружается.

| Состояние | Что оно подтверждает |
| --- | --- |
| «Редактор готов» | Документ открыт для работы |
| «Есть неотправленные правки» | SDK сообщил о локальных изменениях |
| «Правки на сервере редактора» | SDK подтвердил передачу изменений Document Server |

Последнее состояние не означает «Сохранено в HUB». Существующий механизм передаёт итоговый файл в HUB
через callback после завершения совместной сессии. Промежуточное подтверждение SDK не выдаётся за
завершённую запись в хранилище HUB.

Кнопка закрытия в общей шапке, Escape и закрытие fallback-диалога вызывают `requestClose`. SDK сам
проверяет неотправленные данные и только после подтверждения присылает `onRequestClose`. Обновление
или закрытие вкладки с неотправленными правками вызывает стандартное предупреждение `beforeunload`.
Ручное переоткрытие после правок требует подтверждения с предложением сначала сохранить копию
средствами редактора или скопировать важный текст.

Это сохранение действующего окна при сбое сети. Новое хранилище локальных черновиков и автономное
редактирование не добавляются; закрытие/аварийное завершение браузера не гарантирует сохранность
непереданных данных.
