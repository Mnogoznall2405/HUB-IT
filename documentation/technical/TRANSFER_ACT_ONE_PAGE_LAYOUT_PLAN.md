# План: акт передачи — подписи на первой странице

Дата: 2026-09-30. Роли: исполнитель — агент, проверяющий — отдельный ревьюер.

**Статус:** этап 1 выполнен и принят на проверке (см. «Результат проверки этапа 1»). Открыт этап 2 — «Доработка: подпись HUB-IT в колонтитуле» в конце документа.

## Цель

Акт передачи во временное пользование (`templates/docx_transfer_act.docx`) при 1–8 позициях техники должен помещаться на одну страницу вместе с подписями. При большем количестве подписи не должны оставаться на странице одни, а каждая страница должна идентифицироваться колонтитулом.

## Исходное состояние (baseline, замер по последним 300 PDF в `transfer_acts/`)

| Позиций | 1 страница | 2+ страниц |
|---|---|---|
| 1 | 147 | 0 |
| 2 | 45 | 7 |
| 3 | 32 | 16 |
| 4 | 0 | 25 |
| 5+ | 0 | все |

Причины в шаблоне:

1. Шапка собрана из абсолютно позиционированных рамок (`w:framePr`, `vAnchor="page"`), под ними 10 пустых абзацев Tahoma 12 pt (~145 pt) только чтобы отодвинуть таблицу.
2. Пустые абзацы: после таблицы техники, после «Сотрудник принимает на себя…», два перед блоком подписей (~55 pt суммарно).
3. Блок подписей: внешняя таблица 1×1 с `cantSplit`, внутри сетка 4×3 с пустой строкой (~77 pt). При нехватке места уезжает целиком и без текста.
4. Заголовок «Инвентарный номер» в колонке 1200 twips переносится на 3 строки; длинные серийники — на 2.
5. «1/1» и «IT Invent» внизу — статичный текст в рамках (`y=16246`), а не колонтитул; в 2-страничных актах всё равно «1/1», при 3 позициях подписи почти налезают на него.
6. Поля страницы: top/bottom 288 twips, left 720, right 274; ширина таблиц 11046 twips с `tblInd -152` больше области текста (10914).

## Согласованные решения (не менять без пользователя)

- «Выдал» — как сейчас: `{{FROM_EMPLOYEE}}` (прежний владелец / «Без владельца»).
- Должности в подписи не добавлять.
- Номер акта в шаблоне НЕ печатать. Номер `№…` по-прежнему ставится штампом при загрузке подписанного скана (`act_upload_service._stamp_pdf_doc_no`: левый верхний угол первой страницы, x≈18 pt, верх текста ≈18–28 pt от верхнего края). Этот угол в новом шаблоне должен оставаться пустым.
- Цель: 6–8 позиций на одной странице, шрифт текста обязательств остаётся 10 pt.
- Шапка — тот же состав и порядок строк, визуально близко к текущей, но компактнее.
- Текст обязательств (пункты 1–14 и два завершающих абзаца) — слово в слово, без правок.
- Для 2+ страниц: колонтитул «Акт от ДД.ММ.ГГГГ · Стр. X из Y» на каждой странице, повтор шапки таблицы, подписи переносятся только вместе с последними абзацами текста.

## Вне объёма

- Изменение логики DOC_NO / ITINVENT, `act_upload_service.py`, штампа.
- Изменение текста обязательств, реквизитов, состава колонок таблицы и заголовков колонок.
- Копии шаблона в `deploy_staging/` и `_restored_from_git_*` — не трогать.
- Deployment, перезапуск backend/bot, изменение `.env`.

## Работы

### 1. Шаблон `templates/docx_transfer_act.docx`

Файл отслеживается git (rollback — `git show HEAD:templates/docx_transfer_act.docx`). Рекомендуется собирать новый шаблон воспроизводимым скриптом (python-docx + lxml) из текущего, скрипт положить в `scripts/` только если он нужен для повторной сборки; иначе держать во временной папке.

1.1 Шапка:
- Удалить все абзацы с `w:framePr` и 10 пустых абзацев-распорок.
- Воссоздать шапку обычным потоком (абзацы или таблица без границ) в том же порядке: верхняя линия; дата `{{DATE}}` справа; заголовок «АКТ ПЕРЕДАЧИ ВО ВРЕМЕННОЕ ПОЛЬЗОВАНИЕ ОБОРУДОВАНИЯ, ПРИНАДЛЕЖАЩЕГО КОМПАНИИ» по центру, жирный; «ООО "Запсибгазпром-Газификация"»; «Компания ООО "Запсибгазпром-Газификация"»; «предоставляет сотруднику»; `{{TO_EMPLOYEE}}` с линией снизу; «во временное пользование следующее оборудование:». Шрифт Tahoma, размеры как сейчас (9.5 pt шапка).
- Левый верхний угол (примерно 0–70 pt по X, 0–35 pt по Y от края страницы) — без текста. Дата справа там не мешает.
- Placeholder каждого поля должен целиком находиться в одном абзаце (см. `_replace_document_placeholders` — она склеивает runs абзаца в первый run).

1.2 Таблица техники (`document.tables[0]`):
- Сохранить 6 колонок, заголовки и порядок (тест проверяет `EXPECTED_HEADERS`).
- Пересчитать ширины колонок в пределах области текста (без выхода за правое поле), чтобы «Инвентарный номер» занимал ≤ 2 строк, а серийник до 20 символов и инв. номер помещались в одну строку. Новые ширины отразить в `EXPECTED_GRID_WIDTHS` теста.
- Строка заголовка: `w:tblHeader` (повтор на каждой странице).
- Строки данных не должны разрываться между страницами (`w:cantSplit`). Строка-шаблон `rows[1]` удаляется кодом, а `table.add_row()` создаёт `w:tr` без `trPr`, поэтому `cantSplit` выставляется в коде для каждой добавленной строки (см. п. 2).
- Убрать пустой абзац после таблицы; отступ задать `spacing before` у следующего абзаца (≈ 6 pt).

1.3 Текст обязательств:
- Текст не менять. Убрать пустой абзац после «Сотрудник принимает на себя следующие обязательства:» (заменить на spacing).
- Абзацы «Материальные ценности проверены…» и «Настоящий акт составлен…» — `keepNext` + `keepLines`, чтобы при нехватке места переходить на следующую страницу вместе с подписями.

1.4 Блок подписей (`document.tables[1]`):
- Удалить два пустых абзаца перед ним; отступ сверху через spacing (≈ 12–18 pt, чтобы было место для подписи).
- Сохранить внешний контейнер 1×1 с `cantSplit` и вложенную сетку 4×3 с текстами «С условиями ознакомлен:» / «Выдал:», `{{TO_EMPLOYEE}}` / `{{FROM_EMPLOYEE}}`, строку подписи, «(подпись)» — тест проверяет эту структуру. Уменьшить высоту: строка под подпись — фиксированная высота, достаточная для подписи от руки (≈ 20–24 pt), с линией снизу; остальные строки без лишних отступов.
- Все абзацы блока `keepNext` (уже есть), `keepLines`.
- Пустой абзац после таблицы (обязателен в Word) — минимальный размер шрифта (1 pt) и `spacing 0`, чтобы он не создавал пустую страницу.

1.5 Колонтитул:
- Удалить статичные рамки «1/1» и «IT Invent».
- Добавить нижний колонтитул секции: слева «Акт от {{DATE}}», справа «Стр. `PAGE` из `NUMPAGES`» (Tahoma 8 pt, серый как сейчас). Реализовать таблицей без границ 1×2 или табуляцией; поля PAGE/NUMPAGES — в отдельном абзаце/ячейке, где нет placeholder'ов (иначе замена runs уничтожит `fldChar`/`instrText`). Надпись «IT Invent» можно сохранить в колонтитуле, если помещается.
- Нижнее поле страницы и `footer` distance подобрать так, чтобы колонтитул не перекрывал текст (сейчас `w:footer=720` при `w:bottom=288`, колонтитула нет).

## Этап 2. Доработка: подпись HUB-IT в колонтитуле

Решение пользователя: в колонтитуле актов вместо «IT Invent» должно быть «HUB-IT» (именно в таком написании).

Работы:

1. `templates/docx_transfer_act.docx`: в нижнем колонтитуле заменить текст «IT Invent» на «HUB-IT». Больше ничего в шаблоне не менять (вёрстка, отступы, размеры шрифта — как после этапа 1).
2. `scripts/rebuild_transfer_act_template.py`: заменить «IT Invent» на «HUB-IT» (строка с `_footer_text_run("IT Invent")` и docstring), чтобы повторная сборка давала тот же результат. Шаблон после этапа 1 уже без `w:framePr`, скрипт при повторном запуске ничего не делает («already rebuilt») — поэтому правку в `.docx` внести точечно (python-docx по run'у в колонтитуле), не пересобирая шаблон.
3. Цвет текста колонтитула сделать темнее: `808080` вместо `C0C0C0` (все run'ы колонтитула, включая поля PAGE/NUMPAGES), размер шрифта не менять. Синхронно обновить скрипт сборки.
4. `tests/test_transfer_act_document_layout.py`:
   - проверять, что в колонтитуле есть «HUB-IT» и нет «IT Invent» ни в колонтитуле, ни в теле документа;
   - проверку полей сделать точной: `instrText`, нормализованный `strip()`, равен `PAGE` и отдельно равен `NUMPAGES` (например, собрать множество значений `w:instrText` и проверить `{"PAGE", "NUMPAGES"} <= set`).

Не трогать: код `transfer_service.py` и `bot/services/pdf_generator.py` (для этапа 2 правки не нужны), остальное — по разделу «Вне объёма».
