# VoiceVideo (протоколы встреч) — архитектура и эксплуатация

Отдельный контур поверх пайплайна `voice_video/` (бывший `C:\Project\VoiceVideo`,
перенесён в монорепо). Паттерн повторяет Scan Center: независимый FastAPI-процесс,
отдельный worker, auth через основной backend, реестр в PostgreSQL.

## Компоненты

| Компонент | Где | Порт/назначение |
|---|---|---|
| Voice API | `voice_server/app.py` (`python -m voice_server`) | `127.0.0.1:8013`, префикс `/api/v1/voice` |
| Worker | `voice_server/worker_main.py` (`python -m voice_server.worker_main`) | опрашивает очередь, запускает `voice_video/run.py` сабпроцессом |
| Пайплайн | `voice_video/` | Whisper/pyannote, CUDA; данные не коммитятся (см. `.gitignore`) |
| Реестр | PostgreSQL schema `voice`, таблица `voice_jobs` | метаданные задач, настройки, отчёты, спикеры |
| Frontend | `/voice` | `pages/voice-video/*`, права `voice.*` |

Файлы (медиа, отчёты, сэмплы спикеров) хранятся в `voice_video/input|output|unassigned_speakers|reference_voices`;
в БД — только пути и метаданные.

## Права

- `voice.read` — страница, протоколы, отчёты, прослушивание сэмплов. Все read-пользователи видят все протоколы.
- `voice.upload` — загрузка медиа и постановка задач.
- `voice.manage` — именование спикеров, запись эталонных голосов, resume.

Выдача — стандартный интерфейс прав в `account`. Auth: voice_server проверяет токен через
`/api/v1/auth/me` основного backend (`VOICE_AUTH_ME_URL`); forwarded-заголовки из IIS сохраняют
admin IP-allowlist.

## Конфигурация (.env)

- `VOICE_DATABASE_URL` — PostgreSQL (`schema voice`); если пусто — `APP_DATABASE_URL`.
- `VOICE_SERVER_PORT` — по умолчанию 8013.
- `VOICEVIDEO_ROOT` — корень пайплайна (по умолчанию `<repo>/voice_video`).
- `VOICEVIDEO_PYTHON` — интерпретатор с torch/whisperx (по умолчанию текущий python).
- `VOICE_WORKER_CONCURRENCY` — 1 (GPU-bound; поднимать только при запасе VRAM).
- `VOICE_JOB_TIMEOUT_SEC`, `VOICE_UPLOAD_MAX_BYTES` — лимиты.

## Развёртывание

```bash
# 1. Миграция схемы voice (нужен VOICE_DATABASE_URL или APP_DATABASE_URL)
python -m alembic -c voice_server/alembic.ini upgrade head

# 2. Процессы (только voice или весь набор)
pm2 start scripts/pm2/ecosystem.voice.config.js
pm2 start scripts/pm2/ecosystem.all.config.js   # включает voice

# 3. IIS — правило "Voice API Reverse Proxy" уже в public/web.config:
#    /api/v1/voice/* -> http://127.0.0.1:8013/api/v1/voice/*
```

Frontend ходит в `/api/v1/voice/*` через тот же origin, что и остальные API.

## Разметка диаризации (вкладка «Разметка»)

Ручная разметка «кто когда говорит» для оценки и настройки диаризации. Доступ — `voice.manage`.

1. `POST /api/v1/voice/labeling/projects` — загрузка медиа в `voice_video/labeling/<id>/`,
   запись в `voice.label_projects`, задача `kind=label` в общей очереди.
2. Worker запускает `voice_video/label_draft.py`: диаризация pyannote по **сырому** звуку
   (16 кГц моно, без сепаратора вокала), опционально текст реплик через обычный STT
   (сепаратор → нормализация → STT). Результат — `draft.json` и `audio.mp3` для плеера.
3. Черновик сохраняется в `auto_segments` и, пока никто не правил, в `segments`.
4. Редактор (`VoiceLabelEditor.jsx`): плеер, шкала реплик, смена спикера, разрез/слияние,
   границы по плееру, выбор сотрудника для метки (`/hub/users/assignees`, нужен `tasks.read`;
   без него — ввод имени вручную), объединение меток, отмена, автосохранение.
5. `PUT .../projects/{id}` — сохранение с оптимистической блокировкой по `version`
   (устаревшая вкладка получает 409, чужие правки не затираются).
6. `GET .../projects/{id}/rttm?source=edited|auto&names=0|1` — эталон и черновик модели
   в формате RTTM для подсчёта DER.
7. Волна звука (`peaks.json`, огибающая по 0,1 с) и масштабируемая шкала: границы выбранной
   реплики перетаскиваются мышью.
8. «Качество диаризации»: `GET .../metrics` считает DER (пропуск / лишнее / путаница, допуск
   ±0,25 с, оптимальное сопоставление спикеров) черновика и вариантов против сохранённой
   разметки (`voice_server/labeling_metrics.py`). `POST .../variants {separator}` ставит
   задачу диаризации того же файла по очищенному звуку (`label_draft.py --mode variant`).
9. «Записать голоса в эталоны»: `POST .../enroll` режет до 30 с самых длинных сохранённых реплик
   каждого названного сотрудника (`--mode samples`, звук после сепаратора — как у
   автоопределения в протоколах) и вызывает `run.py --enroll-voice`.
10. «Лица участников» (только для видео): `POST .../faces/scan` запускает `face_cluster.py scan --segments`
    (кадры только вокруг реплик, шаг 6 с) → кластеры лиц в `labeling/<id>/faces/`; `GET .../faces` отдаёт
    кластеры с превью (`.../faces/thumbs/{id}`, `Cache-Control: no-store`) и подсказкой «кто звучал в эти
    моменты». Человек вписывает ФИО (список — эталоны лиц и имена из разметки), `POST .../faces/enroll`
    вызывает `face_enroll.py apply` → `voice_video/data/face_roster.json`, затем по умолчанию `purge`
    (превью и векторы удаляются — биометрия не хранится дольше нужного). `DELETE .../faces` — удалить
    превью вручную. Заметки: запись идёт в тот же `face_roster.json`, что и автопополнение при
    обработке видео, — не запускать одновременно с массовым прогоном `bank_eval.py`.

Варианты и запись эталонов идут отдельной задачей (`aux_job_id`), разметка в это время
остаётся доступной для правки. По итогам сравнения основной пайплайн переключается
переменной `DIARIZATION_AUDIO=raw|processed` в `voice_video/.env` (по умолчанию `processed` —
как было); распознавание текста всегда идёт по обработанному звуку.

Таблица создаётся миграцией `20261002_0005` (как и остальные — явной командой при релизе).

## Флаги качества диаризации (`voice_video/.env`)

Все по умолчанию выключены — поведение протоколов прежнее, включать по результатам
сравнения на вкладке «Разметка» или по наблюдению за протоколами:

| Переменная | Что делает |
|---|---|
| `DIARIZATION_AUDIO=raw` | диаризация по сырому звуку (STT — всегда по обработанному) |
| `DIARIZATION_OVERLAP_ASSIGN=1` | спикер слова — по наибольшему пересечению с репликой (`modules/speaker_utils.py`); при одновременной речи выбор детерминированный, без «последний записанный победил» |
| `SPEAKER_EMBEDDINGS_IMPROVED=1` | эмбеддинги для узнавания: до 30 самых длинных «чистых» реплик (без мест, где по диаризации говорит кто-то ещё), центральные ≤8 с, нормированные векторы; новые эталоны тоже нормируются |
| `DIARIZATION_EXCLUSIVE=1` | `exclusive_speaker_diarization` community-1 (pyannote.audio ≥ 4): один говорящий в момент времени — так модель рекомендует сопоставлять с STT; pipeline вызывается напрямую (WhisperX отдаёт только обычную разметку), при ошибке — обычная |
| `DIARIZATION_CHUNK_SECONDS=900` | чанковая диаризация длинных записей (0 — выключена). Запись длиннее `DIARIZATION_CHUNK_THRESHOLD_SECONDS` (1800) режется на окна с перекрытием `DIARIZATION_CHUNK_OVERLAP_SECONDS` (30); окна сшиваются в общий реестр голосов **без потолка на число спикеров** (`DIARIZATION_CHUNK_MAX_SPEAKERS`, 20, — предел одного окна). Сшивка: якоря по сольной речи в зоне перекрытия, косинус эмбеддингов (`DIARIZATION_STITCH_SIMILARITY` 0.80, `_MARGIN` 0.08, `_MIN_SPEECH` 6 с), без принудительных склеек; в конце — поглощение островков и слияние дублей (прототипы ≥ similarity−margin, не звучали в одном окне, не говорят одновременно). Неоднозначные голоса и конфликты на границе — в `review_speakers`: авто-ФИО для них не ставится. Окна кэшируются рядом с WAV (`*_diar_window_NNNN.json`), ключ — аудио, модель, параметры. Нужен pyannote.audio ≥ 4; любая ошибка окна — ошибка обработки (не пустой протокол). Замер: ВКС 136 мин, T4 — 5.7 мин, 14 разных людей по эталонам вместо 11 при потолке 10; окна 900 с стабильнее 600 с |
| `JEV_DOMAIN_TAGS=1`, `JEV_PROTOCOL_GUARD=1` | Jev как контролёр протокола (`modules/protocol_guard.py`, транспорт — `shared.llm.jev_client`). Направление каждой темы (стройка, документация, ПНР, снабжение, финансы, персонал, юристы, ИТ) с уверенностью и второй по вероятности меткой — в сводке «На что ушло время». «Сторож» проверяет каждое поручение реестра: следует ли оно из транскрипта темы (окно вокруг слов поручения, порог `JEV_GUARD_SUPPORT_MIN` 0.4) и назначен ли ответственный (метка `SPEAKER_xx` — детерминированно). Сомнительные не удаляются, а получают «⚠ проверить: причина» (в интерфейсе — чип «Проверить»; ключ статуса поручения от пометки не зависит). Замер на ВКС: настоящие поручения 0.80, чужой фрагмент 0.11; ложно помечено 2 из 30 (оба расплывчатые). Сбой Jev — протокол без меток |
| `GLOSSARY_PROMPT=1`, `GLOSSARY_CORRECT=1`, `GLOSSARY_EXTRACT=1` | Словарь компании (вкладка «Словарь», таблица `voice.glossary_terms`, миграция `20261004_0007`). После каждой записи Luna (~0.7 цента) предлагает кандидатов (аббревиатуры, объекты, подрядчики, ошибки распознавания) → `<base>_glossary_candidates.json` → очередь подтверждения. Подтверждённые выгружаются в `voice_video/data/company_glossary.json`. Промпты: только термины, звучащие в записи, плюс ядро (`core`), потолок 1800 символов (`format_prompt_block`); подсказка STT — до 30 имён/объектов. Корректор заменяет подтверждённые неверные написания точными совпадениями целых слов, без LLM. Расшифровки не выдумываются: «?» остаётся пустым, пока человек не заполнит |
| `cut_silence.py` | Вырезание тихих мест из длинной записи (видео без перекодирования, границы по ключевым кадрам, карта времён `*.silence_map.json`: точность 1–2 мс). `VOICE_AUTO_*` для сервера: `VOICE_CUT_SILENCE_MIN_DURATION_SEC` (0 — выкл.) вырезает тишину при загрузке записей длиннее порога, карта сохраняется в `settings.silence_cut` |
| `suggest_fragments.py`, `eval_labels.py` | Автоподбор самых полезных для разметки фрагментов (два прогона со сдвигом окон: где расходятся, перебивания, редкие голоса; MP4 без перекодирования) и регресс диаризации на ручных разметках (`export`/`run`, DER и путаница против базы). `VOICE_AUTO_ENROLL=1` — имя спикера в сохранённой разметке автоматически записывает голос в эталоны (режим «слить», только новые назначения) |
| `DEAD_AIR_SECONDS=600` | Участки записи без звука дольше N секунд (`modules/dead_air.py`) вырезаются перед нормализацией и возвращаются тишиной: длина файла и тайм-коды те же. Видео-подсказки (`speech_windows`) читают кадры только вокруг реплик. Запись 22.07: 18 ч, звук в ~40 мин. 0 — выкл. |
| `AUDIO_LOUDNORM=1` | Нормализация громкости по стандарту вещания (−16 LUFS, `modules/loudness.py`) вместо пиковой. Облачный STT теряет слова на тихом звуке; замер на ВКС (3 окна × 5 мин): расхождение Gemini со вторым распознавателем на сыром звуке 13.1 %, с Kim 8.1 %, с loudnorm 6.7 %; компрессор и −14 LUFS дают ≤0.5 п.п. (шум). С ним сепаратор не нужен (`SEPARATOR_ENGINE=none`): Kim на записи 2.5 ч — ~25 мин, loudnorm — ~3 мин; Kim на этой записи речь не гасил (0 из 158 реплик заглушено >6 дБ) |
| `staff_glossary.py` (запуск вручную) | Руководители и объекты в словарь: оргструктура, роли на объектах (`app.org_structure_nodes`, `app.construction_*`) адресная книга (только руководители по должности: директор, заместитель, главный инженер/ГИП, начальник, руководитель, управляющий; флаг `--everyone` — все сотрудники; хранятся ФИО, должность, подразделение, город, уволенные и контакты отбрасываются) и ручной список `data/staff_manual.txt` («ФИО | должность | подразделение или объект») -> `data/staff_glossary.json`. Загрузчик глоссария подхватывает файл рядом с `company_glossary.json`; поле `match` (варианты имени «Фамилия И.О.», «Имя Отчество») нужно только для подбора в промпт, текст расшифровки имена не заменяют. Только чтение БД; список объектов вкладки «Объекты строительства» живёт в памяти бэкенда (живой запрос к 1С), в файл не попадает |
| `VIDEO_HINTS=1` | «Кто говорит» по видео ВКС (`video_speaker_hints.py`, TrueConf): рамка активного говорящего (оранжевое кольцо) + подпись плитки локальным EasyOCR (кадры не уходят наружу). Сводка `<base>_video_hints.json`: `suggested` — имя безымянному голосу (≥70 % подсвеченной речи, ≥20 с), `rooms` — состав комнат (голоса при подсветке плитки-комнаты), `conflicts` — голос назван по эталону, а аккаунт-плитка подписана другой фамилией (общий аккаунт или ошибка опознания), `mixed` — один голос подсвечивает разных людей (склейка в диаризации). Только подсказки. Замер на 3 окнах по 10 мин: Москва→Водопьянов 97–99 %, СПб→Миронов 100 %, Белушья губа→Каримов 94 %, плитки людей 91–99 % |
| `FACE_HINTS=1` | **Биометрия** (включать после согласования с ИБ/юристами; нужен `VIDEO_HINTS=1`). Опознание лица в подсвеченной плитке (`face_roster.py`: YuNet+SFace из OpenCV Zoo, локально на CPU; модели кладутся в `voice_video/data/face_models/`, в git не входят). Эталоны набираются без разметки по согласию голоса и плитки (плитка с одним голосом ≥80 %, ≥8 кадров) и хранятся только как векторы в `FACE_ROSTER_PATH` (`data/face_roster.json`, в git не входит); фото не сохраняются. В `<base>_video_hints.json` → `faces`: `tiles` (кто виден на плитке), `face_voice_conflicts` (лицо ≠ названному голосу на плитке-человеке), `enrolled`. Замер: лицо→имя 96 % при эталонах из других окон (103 кадра, 4 человека — малая выборка) |
| `SPEAKER_RECURRING=1` | неизвестный голос, похожий (≥ `SPEAKER_RECURRING_SIMILARITY`, 0.6) на неизвестный из другой встречи, получает общий id; в карточке — «встречался ещё в N записях». Реестр `voice_video/data/recurring_voices.json`, пишет только worker |
| `SPEAKER_ID_STRICT/MODERATE/LOOSE` | пороги узнавания (косинусное расстояние), по умолчанию 0.25/0.35/0.45 |

Подбор порогов: вкладка «Разметка» → «Подбор порога узнавания» (`POST .../calibrate`,
`label_draft.py --mode calibrate`) считает похожесть каждого названного сотрудника с каждым эталоном
тем же способом, что в протоколах; `GET /labeling/calibration` сводит все разметки и предлагает
значения для `.env` (при пересечении «свои/чужие» — порог против ложных имён). Для оценки брать
встречи, из которых эталоны не записывались.

Сравнение вариантов в «Качестве диаризации»: сепаратор или «без сепаратора» + «эксклюзивная разметка».

Если локальной модели `wespeaker-voxceleb-resnet34-LM` нет, в лог пишется предупреждение:
используется старая `pyannote/embedding`, узнавание по голосу хуже.

Диапазон спикеров: в форме загрузки «Участников от/до» -> `run.py --min-speakers/--max-speakers`
(точное число, если задано, важнее диапазона).

## Поручения

- Реестр: LLM возвращает JSON (`action_registry_prompt.txt`), таблицу собирает
  `modules/action_registry.py` — «|» в тексте и пропущенные колонки больше не ломают разбор.
  Если модель ответила таблицей, она используется как есть.
- Статусы (`voice.voice_assignment_statuses`) привязаны к `item_key` — хэшу раздела и
  формулировки поручения (`pipeline.assignment_key`), а не к номеру строки. После пересборки
  реестра статус остаётся у своего поручения; переформулированное поручение начинает с
  чистого статуса. Старые строки без ключа получают ключ текущей строки с тем же номером:
  при первом чтении статусов и перед `resume`-задачей (до пересборки).
- `task_id` — созданная из поручения задача; повторно создать её из интерфейса нельзя.
- Дата встречи для сроков: флаг/форма → имя файла → `creation_time` из метаданных записи.
- Миграция `20261002_0006`: колонки `item_key`, `task_id`, уникальность `(base_filename, item_key)`
  вместо `(base_filename, num)`.

## Эксплуатационные замечания

- Одна GPU (Tesla T4): `VOICE_WORKER_CONCURRENCY=1` — очередь последовательная.
- Пайплайн использует глобальные каталоги `voice_video/`; параллельные задачи не предполагаются.
- `torchcodec`/FFmpeg warning от pyannote при импорте — наблюдаемая проблема среды; если
  диarization падает на декодировании, проверить FFmpeg в PATH пайплайна.
- Логи пайплайна — `voice_video/logs/`, stdout сабпроцесса — в логах pm2 `itinvent-voice-worker`.
- Ротация/ретенция отчётов — средствами самого пайплайна (`output/`, `processed/`); БД хранит пути.
