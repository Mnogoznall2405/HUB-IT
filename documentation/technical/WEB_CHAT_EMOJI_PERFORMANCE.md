# WEB_CHAT_EMOJI_PERFORMANCE — производительность Emoji/Sticker Picker

Дата: 2026-11-23. Ветка `feat/chat-emoji-picker-telegram` (PR #17).
Объект: `ChatEmojiPanel` / `ChatEmojiDock` / `TelegramStickersTab` /
`useChatComposerUiController` / `useChatThreadSection` / `ChatThread` (popover).

## Методика

- Playwright + Performance API + Resource Timing + `performance.memory` +
  `PerformanceObserver(longtask)`. Стадии опрашиваются каждый rAF из самой
  страницы (t0 — capture-фаза клика), не из Playwright-поллинга.
- Спек: `frontend/e2e/chat-emoji-perf.spec.js`, 20 прогонов на сценарий,
  p50/p95, viewport 1440×900, сид `e2e_test_pack` (~90 стикеров).
- Артефакты: `e2e-artifacts/emoji-picker/perf-deep.json` (после),
  `perf-deep-before.json` (до) — оба против **production-сборки**
  (`E2E_BUILD=1`, `vite preview`). Dev-замеры (vite dev + React dev) ~2×
  медленнее и приведены только для истории.

«Полезное содержимое» = первый видимый эмодзи с реально загруженной
картинкой (`img.complete && naturalWidth>0`), не присутствие кнопки в DOM.

## Стадия за стадией (cold, после)

```
клик → контейнер        ~103 мс   (React render + layout колонки)
     → интерактив       ~138 мс   (поиск доступен раньше эмодзи)
     → emoji в DOM      ~205 мс   (mount пикера)
     → emoji загружен   ~419 мс   (+~190 мс fetch/decode 180 img)
     → все декодированы ~1000 мс  (180 картинок, ~723 КБ)
```

## Что изменено и измеренная причина

### 1. Idle-прогрев цепочки чанков — `useChatComposerUiController.js`

**Причина:** `prefetchEmojiPanel` грел только обёртку
`ChatEmojiPanel`; тяжёлый чанк `emoji-picker-react` (302 КБ decoded /
75 КБ gzip) грузился по клику — `emojiChunkEnd` ≈1689 мс от навигации,
то есть на критическом пути первого открытия.

**Изменено:** `requestIdleCallback` после монтирования чата +
prefetch на `pointerenter` теперь импортируют и
`import('emoji-picker-react')` (тот же specifier → тот же чанк).
Чанк приходит ~800–1250 мс — до клика. Picker остался вне начального
бандла (`ChatPageContent` без изменений, 683 КБ).

**Эффект:** холодное открытие больше не ждёт чанк; «полезный контент»
~390–420 мс упирается в fetch+decode картинок, а не в JS.

### 2. Keep-alive дока, поповера и вкладок

**Причина:** `emojiAnchorEl=null` размонтировал весь док,
`TabPanel` возвращал `null` неактивной вкладке → каждое открытие и
каждое переключение платили remount `emoji-picker-react` и сетки
стикеров; 100 циклов открытия наращивали heap +14.6 MB churn-ом.

**Изменено:**
- `useChatThreadSection`: латч `emojiDockEverOpened` — док после первого
  открытия остаётся смонтированным и скрывается `display:none`
  (`hidden`-проп в `ChatEmojiDock`). Измерение ширины не ломается:
  `parentElement` — прежний `chat-thread-pane-wrap`.
- `ChatThread`: тот же латч для hover-поповера
  (`emojiPopoverEverVisible`).
- `ChatEmojiPanel/TabPanel`: монтируется при первой активации или по
  idle-прогреву (`forceMounted`), дальше скрывается стилем — скролл,
  поиск и состояние epr сохраняются между вкладками и между
  открытиями, как в Telegram.
- Idle-прогрев скрытой вкладки монтирует её заранее (картинки стикеров
  при этом не грузятся — `display:none` вне IntersectionObserver).

**Эффект:** warm-open 140→115 мс (все стадии схлопнулись в один кадр —
контент уже в DOM), возврат «Стикеры→Эмодзи» 182→143 мс, heap за 100
циклов плоский (−12.3 MB — GC свободно собирает; churn remount
устранён). Цена: ~+560 припаркованных DOM-узлов и ~+20 MB heap
одноразово — принято для desktop-UX; зафиксировано.

### 3. `memo()` для пикера + стабильные пропы — `ChatEmojiPanel.jsx`

**Причина:** любой ре-рендер панели (переключение вкладки, toggle
keep-alive) перерендеривал сетку epr: инлайн `categories`,
`previewConfig` и `onEmojiClick` делали memo бесполезным.

**Изменено:** `MemoEmojiPicker = memo(LazyEmojiPicker)`, константы
`EMOJI_CATEGORIES`/`EMOJI_PREVIEW_CONFIG` вынесены на модульный уровень,
`handleEmojiClick` — `useCallback`; `StickersTab` — `memo`. При
переключениях epr и вкладка стикеров не перерендериваются вовсе.

### 4. Hover-задержка 260 → 140 мс

**Причина:** пользовательская задержка превью была сверх меры.
**Изменено:** `EMOJI_PREVIEW_OPEN_DELAY_MS = 140`; задержка закрытия
320 мс сохранена (мерцаний при перелёте курсора нет — проверено E2E).
Поповер стал виден за 392→270 мс; контент внутри него — keep-alive —
появляется мгновенно, без спиннера.

### 5. Клик → pinned без искусственных задержек

По клику `setEmojiPanelMode('pinned')` + anchor применяются в одном
батче; с прогретыми чанками и keep-alive док виден за ~110 мс.

## Картинки эмодзи — измерено

- 180 видимых img при открытии, ~723 КБ суммарно
  (локальные `/emoji/apple/64/*.png`, 0 ошибок, 0 повторных запросов).
- `lazyLoadEmojis` ограничивает запросы viewport-ом — не тысячи файлов.
- Полный decode видимого набора ~1 с — это и есть основной остаток
  холодного открытия. 32-px/WebP-варианты сократили бы объём ~вдвое,
  но требуют новой asset-линейки и теряют retina-качество: по замерам
  не критический путь — отложено, зафиксировано как кандидат.

## Стикеры — измерено

- Пак ~90 стикеров: первая активация вкладки ~110–120 мс — это общий
  пол рендера панели, не стикерная работа (API-кэш scoped+epoch, сетка
  `contentVisibility`, lazy thumbnails, IO-gating анимированных).
- Повторные переключения ~20–40 мс реальной работы (в пределах точности
  замера Playwright-поллинга ~100 мс — погрешность задокументирована).
- Гонки кэша, epoch-инвалидация и контракты отправки не тронуты.

## Остаточный пол ~110–140 мс

Каждое открытие/закрытие меняет `emojiAnchorEl`/`emojiPanelMode` в
state `ChatPageContent` → ре-рендер всей страницы + layout
(колонка 360 px сжимает тред). Это архитектурная стоимость, не работа
пикера; заужение state — отдельная задача за рамками этого PR.
В пределах этого пола цели «<80/120 мс» недостижимы без рефакторинга
страницы — фиксируется измеренная причина.

## Long tasks / отзывчивость

- Warm-циклы: 0–2 longtask на 20 открытий, ~50 мс — главный поток свободен.
- Холодные: 0–1 longtask на открытие.
- Композер остаётся отзывчивым (поиск пикера интерактивен за ~140 мс,
  вставка не блокируется загрузкой картинок).

## Регрессионная проверка

- Playwright `chat-emoji-picker.spec.js`: 14/14 (viewport 988–1920,
  hover/pinned/overlay, светлая+тёмная темы, вставка эмодзи,
  двухаккаунтная доставка стикеров, дедуп, retry, Escape).
- Playwright `chat-emoji-perf.spec.js`: 20-прогонный инструментальный
  сьют — зелёный на dev и prod-сборке.
- Vitest затронутых файлов: 120 тестов — зелёные.
- `vite build`: чистый; `emoji-picker-react` — отдельный lazy-чанк
  302 КБ (75 КБ gzip), вне начального бандла.
- Память: без утечек DOM и heap за 100 циклов (см. таблицу).

## Известные ограничения

- Цели 80/120 мс для вкладок упираются в пол рендера страницы
  (~110–140 мс) и точность Playwright-поллинга — не в remount.
- Первое посещение вкладки «Стикеры» до idle-прогрева платит mount
  ~100 мс одноразово.
- Мобильный inline-пикер остаётся remount-per-open — осознанная
  экономия памяти; desktop-паттерны туда не переносились.
