### Исправление U14–U18 по запросу «исправляй»

Все пять пунктов реализованы локально:

- **U14:** отдельный guard операции сохранения, привязанный к requestId. Сохранение A может закончить свою серверную операцию и обновить общий список, но не перезагружает открытую B и не меняет её ошибку/loading. При переключении карточки сбрасываются локальный saving и комментарий статуса.
- **U15:** guard загрузки сотрудника учитывает открытие диалога и право чтения персональных данных. Новый выбор, очистка поля, ручное добавление и переход к импорту ЗУП инвалидируют предыдущую загрузку; поздние ответы/ошибки не вызывают applyEmployee.
- **U16:** отдельное поколение запроса деталей документа движения. Новое открытие и закрытие инвалидируют старый запрос; success/catch/finally обновляют только актуальную карточку.
- **U17:** введено состояние завершённой попытки загрузки баз, отдельная ошибка и кнопка «Повторить загрузку баз». Ошибка больше не возвращает загрузчик в состояние автоматического старта; loaded остаётся false до настоящего успеха. Другая успешная загрузка настроек не скрывает ошибку баз.
- **U18:** экспорт обрабатывает ошибку существующим UI-механизмом, показывает занятость, блокирует повторный запрос и освобождает блокировку в finally; успешное скачивание сохранено.

Изменены: `WEB-itinvent/frontend/src/components/tickets/TicketRequestCard.jsx`, `TicketEmployeeCard.jsx`, `TicketRequestList.jsx`; `src/pages/Warehouse1C.jsx`; `src/pages/account/hooks/useAccountSectionData.js`; `src/pages/account/AccountWorkspace.jsx` и его тест. Добавлен `src/uiAuditRegressions.test.jsx`. Документ — этот файл.

Пять регрессионных сценариев сначала **упали на неисправленном коде**, затем прошли после исправлений. Дополнительно проверены закрытие сотрудника/документа до ответа, успешное скачивание и защита экспорта от повторного вызова, доступность UI-кнопки повторной загрузки баз. ### U01. Новый PWA worker активируется без согласованного перехода версии

**Файлы:** `WEB-itinvent/frontend/public/sw.js:880–899`; `src/main.jsx:71`; `src/lib/pwaInstall.js:184–195,266` внутри frontend.

В `install` безусловно выполняется `await self.skipWaiting()`, в `activate` — `cleanupOldCaches()` и `self.clients.claim()`. При этом main.jsx явно предупреждает: `Do not auto skipWaiting here: silent claim without reload breaks lazy route opens`. Обработчик controllerchange перезагружает страницу только при `pendingReloadAfterUpdate`; обычный автоматический takeover перезагрузку не инициирует.

Проба реального install handler: `PWA_INSTALL_SKIP_WAITING_WITHOUT_USER_ACTION 1`. Старый JS в открытой вкладке может оказаться под новым worker после удаления старых cache names. При отсутствии старого lazy chunk на сервере возникает ошибка открытия следующего раздела; offline особенно уязвим. Ошибка конкретного live deployment не воспроизводилась, сочетание lifecycle подтверждено.

**Предложение:** согласовать единую модель обновления: ждать явного применения/безопасной перезагрузки либо сохранять assets старых активных клиентов. Не удалять предыдущие assets до безопасного перехода. Регрессия: две вкладки, открытая форма, новый worker, затем lazy route онлайн и offline.

Комментарий install handler объясняет немедленную активацию доставкой исправлений notificationclick. Это намеренная цель, которую следует сохранить; дефект — несогласованность с жизненным циклом открытого frontend и очисткой его assets, а не сама потребность быстро исправлять push.

### U02. HTTP 503 не приводит к использованию cached shell

**Файл:** `WEB-itinvent/frontend/public/sw.js:522–536`.

`handleNavigationRequest` выбирает `networkResponse || cachedResponse()`. `fetch` не отклоняется при HTTP 503, поэтому ответ аварийного upstream возвращается пользователю даже при наличии корректной оболочки в Cache Storage.

Проба: кеш возвращает `cached shell`, сервер — 503. Результат: `PWA_WITH_CACHE_ON_503 503 upstream unavailable`.

**Предложение:** определить статусы временного отказа, при которых используется сохранённый shell. Не превращать ответы авторизации и API в безусловный cache fallback. Проверить 502/503/504, network reject и отсутствие кеша.

### U03. Desktop не открывает действия, реализованные через blob window.open

**Файлы:** `WEB-itinvent/frontend/src/pages/Networks.jsx:1303–1317,3066`; `src/pages/FileEgress.jsx:1799–1808`; `desktop/Hub.Desktop/MainWindow.xaml.cs:1303`; `Views/SecondaryHubWindow.xaml.cs:328`; `Security/NavigationPolicy.cs:29–43,74–80`.

Схема сети открывается через `window.open(mapBlobUrl, '_blank', ...)`. HTML-отчёт FileEgress создаёт `URL.createObjectURL(blob)` и тоже вызывает `window.open`. В обоих Desktop-окнах `NewWindowRequested` сразу помечается обработанным; `blob:` не является trusted origin и отсутствует в списке разрешённых внешних схем. Итог — блокировка вместо открытия; пользователю выводится не ошибка UI, а только запись в native log.

**Предложение:** поддержанный внутренний preview/download или ограниченный bridge для данных, уже полученных приложением. **Не добавлять безусловное разрешение произвольных `blob:`/`data:` URL в navigation policy.** Installed-client smoke обязателен после исправления: схема сети и HTML-отчёт в основном и втором окне.

### U04. Порты устройства A появляются при выбранном B

**Файл:** `WEB-itinvent/frontend/src/pages/Networks.jsx:1087–1097,1237–1248`.

`loadPorts` после await безусловно вызывает `setPorts`. Переключение устройства запускает новый запрос, но не инвалидирует старый. Контекст филиала и общий список портов уже защищены request sequence; здесь защиты нет.

Проба A → B, ответ B → A: `NETWORK_DEVICE_B_PORTS [ 'A-port' ]`.

**Предложение:** request generation по филиалу и устройству, включая сброс выбора. Отклонять старые данные и ошибки. Проверять совпадение выбранного устройства перед операциями с портом. Изменение не того порта на сервере этим аудитом не доказано.

### U05. Поздняя карточка KB подменяет выбранную статью

**Файл:** `WEB-itinvent/frontend/src/pages/KnowledgeBase.jsx:579–641`; соседний `loadCardDetail:598` требует аналогичной проверки.

`loadArticleDetail` после await записывает payload без проверки актуальной selection; `finally` также безусловно очищает loading. При выборе A, затем B, ответ A может стать отображаемой карточкой B. Проба: `KB_SELECTED_B_DETAIL A`. Список дополнительно выбирает ID и вызывает detail loader, поэтому исправление должно учитывать и список, и явный выбор.

**Предложение:** отдельные поколения для article/template/card и запросов списков; согласованность selected ID и detail ID перед показом/действием. Проверить быстрый выбор, фильтр и смену вкладки. Подмена в конкретном production-сеансе не утверждается.

### U06. Старый поиск адресной книги перезаписывает новый

**Файл:** `WEB-itinvent/frontend/src/pages/AddressBook.jsx:97–122`.

Debounce отменяет только таймер. `loadItems` не проверяет актуальность после `addressBookAPI.search`; старый ответ меняет items, total и status, а старый finally снимает loading.

Проба: `ADDRESS_SEARCH_B_SHOWS [ 'A' ]`.

**Предложение:** поколение поиска/AbortSignal и guard для данных, ошибки и loading. Проверить последовательность длинный запрос → короткий → очистка строки. Это предотвращает выбор контакта из выдачи, не соответствующей введённому имени.

### U07. Список паролей не соответствует текущему фильтру

**Файл:** `WEB-itinvent/frontend/src/pages/Passwords.jsx:292–326`.

`loadEntries` записывает результат Promise.all без request guard. При изменении query/group/tag/includeArchived поздний запрос заменяет текущую выдачу; также применяются старые группы, теги и unlocked_until.

Проба с двумя поисками: `PASSWORD_SEARCH_B_SHOWS [ 'A' ]`. **Утечка пароля, обход разблокировки или ослабление backend не доказаны**: проверялась только согласованность состояния списка.

**Предложение:** общий request token для всего результата и его метаданных. Сохранить действующую политику разблокировки и очистки секретов; не кэшировать раскрытые пароли ради исправления поиска.

### U13. Общий файл: 503 выглядит как недоступность/истечение срока

**Файл:** `WEB-itinvent/frontend/src/pages/SharedFile.jsx:38–43`.

`resolvePublicFileError` различает только 429. Для сетевой ошибки и HTTP 503 возвращается «Файл недоступен или срок хранения истёк». Проба с 503 подтвердила этот текст. Он не сообщает о временной проблеме сервиса и может заставить пользователя заново запрашивать ссылку.

**Предложение:** различить network/5xx, 404/410 и ограничения доступа, добавить понятное действие повторной загрузки. Не раскрывать приватные причины отказа публичной ссылки.

## Условные риски и необходимые ручные проверки

1. **R1, cache scope:** `public/sw.js:483–491` удаляет все cache names origin, кроме четырёх собственных текущих имён. Проба удалила `other-app-cache`. Риск для другой PWA/компонента на том же origin подтверждается условием их наличия; фактическое соседнее приложение не обнаруживалось. Ограничить cleanup собственным namespace.
2. **R2, Desktop keyboard:** Release отключает browser accelerator keys; native code явно восстанавливает Ctrl+P/Ctrl+F5 и открытие второго окна. Пользовательский поиск Ctrl+F и zoom keyboard нуждаются в отдельной проверке WebView2. Отключение accelerator keys — явная политика, не повод включать весь набор и DevTools.
3. **R3, остальные гонки:** в загрузчиках Tickets, Warehouse1C и части account/MyFiles есть кандидаты на поздние ответы. Без достоверного сценария на уровне вызывающего UI они не включены в 13 подтверждённых дефектов. Проверить отмену, повтор, смену контекста во время await.
4. **Реальная доступность:** полноценная клавиатурная обходная проверка каждого раздела, NVDA, 200% zoom, high contrast и реальные touch/device scenarios не завершены. Наличие тестов не заменяет это покрытие.
5. **Внешние функции:** реальные VNC, МФУ, принтер, camera/QR, Windows notifications, push в закрытой PWA, подписанный Desktop updater, Exchange/SMTP, 1С/SQL и production-RBAC не проверялись операциями.

## Что намеренно не записано в ошибки

- Безусловное разрешение внешних схем, отключение origin policy, увеличение session lifetime и обход 2FA не предлагаются.
- Отсутствие offline-доступа к бизнес-данным само по себе не дефект: service worker исключает `/api/` из общего shell cache. PWA не обязана сохранять приватные данные offline.
- Request guards уже есть в проверенных загрузчиках construction, detail групп доступа, контекста сети и отдельных preview. Их отсутствие нельзя распространять на весь проект.
- Кликабельные строки MainLayout и администрирования с внутренними доступными «Открыть»/OverflowMenu, а также строка Statistics с clickable Chip не объявлены полностью недоступными только по AST-сигналу.
- `TicketKanban` имеет похожую pointer-only семантику, но его подключение в production frontend не найдено. Он исключён из подтверждённого дефекта текущего маршрута Tickets; U10 относится к реально подключённому TicketRequestList.
- 404 от локального статического сервера до включения API fixtures и ошибки неполных fixture payload — ошибки тестовой среды, не продукта.
- Предыдущие исправления пяти дефектов четырёх страниц остаются отдельным закрытым набором; этот отчёт не отменяет их проверок.
