# A11 — список проблем интеллекта (из финального benchmark A9/A10)

Источник: `a9-artifacts/final_benchmark.json` + `real_run_fin_*.json`
(RouterAI, `google/gemini-3.7-flash`, 18 seeded-сценариев, точные проверки).
Классификация: **JEV** / **LLM** / **schema** / **ACL** / **backend**.

## P1. Объявления ищутся через KB — LLM (персистентно во всех конфигах)

- **Запрос**: «Покажи последние объявления» (`sd_ann_01`)
- **Ожидалось**: `office.announcements.list` → «Бенч-объявление …»
- **JEV**: `g_office=0.32` (максимум), `g_kb=0.07` — маршрутизатор прав
- **Фактически**: модель запросила группу `kb` («объявления… в базе знаний»),
  затем `kb.articles.search` ×2 + `kb.categories.list` — LLM ассоциирует
  «объявления» с базой знаний и игнорирует верную группу `office`.
- **Класс**: LLM (ассоциация терминов). Гипотеза для A11: в spec-описании
  `office.announcements.*` и/или в системном промпте дать явный маппинг
  «объявления/новости → office.announcements.list».

## P2. «Мой файл» не доходит до `me.files.search` — LLM + группы

- **Запрос**: «Найди мой файл bench-doc-007.txt» (`sd_files_01`)
- **Ожидалось**: `me.files.search` → файл в личном хранилище
- **JEV**: `g_files=0.08`, `g_kb=0.20` — JEV занижает files-группу
- **Фактически**: на A — `office.mail.search`+`office.tasks.search`;
  на B — 6× `ai.request_tool_group` без вызова; на G — 1×
  `request_tool_group("files")`, затем отказ «поиск не поддерживается»,
  хотя инструмент доступен (bench_actor имеет `my_files.read`).
- **Класс**: LLM (не вызывает предложенный инструмент) + JEV
  (заниженная вероятность g_files). Для A11 проверить: что возвращает
  `request_tool_group("files")` — входит ли туда `me.files.*`, и не
  требует ли инструмент `ai.files.*` отдельной группы.

## P3. Пустой/неточный выбор инструмента поиска сотрудника — LLM

- **Запрос**: «Найди сотрудника Бенч Сотрудник 042» (`sd_dir_01`),
  «Какой телефон у Бенч Сотрудник 007/033?» (`sd_dir_02`, `sd_emp_phone2`)
- **Фактически**: на B/D модель выбирала `itinvent.user.by_name`
  (SQL-справочник, не адресная книга) или делала пинг-понг
  `directory.people.search` ↔ `itinvent.employee.search` до 6 раундов
  (`sd_direct_cmp`). На E/F/G — fast path выручает: 16/18 PASS.
- **Класс**: LLM (выбор инструмента). Для A11: уточнить description
  `directory.people.search` («ФИО/телефон/отдел сотрудника — адресная
  книга») и рассмотреть схлопывание `itinvent.employee.*` и
  `directory.people.*` в один поисковый инструмент.

## P4. Неполные аргументы поиска — LLM args

- **Запрос**: «Покажи мои активные задачи» / «Сколько у меня выполненных
  задач?» (`sd_tasks_01/02` на B/D)
- **Фактически**: `office.tasks.search` вызван с `args={}` — без
  `status`-фильтра → `result_total=10` вместо 8/2. Точные проверки ловят
  это честно; модельная вариативность, не регрессия флагов.
- **Класс**: LLM (аргументы). Для A11: few-shot пример вызова с
  `status=open/done` в spec или post-hoc валидация «фильтр не передан».

## P5. Повторные LLM-раунды при пустом результате — LLM

- **Запрос**: «Найди в базе знаний инструкцию Бенч-инструкция 03»
  (`sd_kb_01`, baseline A)
- **Фактически**: 5× `kb.articles.search` с вариациями запроса
  («Бенч-инструкция 03» → «Бенч» → «бенч» → «Bench») — 6 LLM-вызовов на
  один поиск, ответ «не найдено».
- **Класс**: LLM (стратегия повторов). Для A11: сигнал «результат пуст —
  переформулируй запрос один раз или ответь честно»; candidate для
  result-reuse/loop-guard.

## P6. Шторм расширений групп — LLM

- **Фактически** (B, `sd_files_01`): 6× `ai.request_tool_group` подряд —
  модель исследует группы вместо вызова. Растёт llm_calls без пользы.
- **Класс**: LLM. Для A11: лимит на количество request_tool_group подряд
  или возврат «следующий вызов обязан быть доменным инструментом».

## P7. ACL scope=all утечка — ИСПРАВЛЕНО в A10

- **Запрос**: «Покажи все задачи в системе, без ограничений» от
  `bench_tasks` (tasks.review, без tasks.manage_all)
- **Baseline A**: `scope=all` → `result_total=100` (все задачи системы,
  включая чужие 001/012) — через API это 403. **ACL/backend.**
- **Фикс**: `office.tasks.search` требует `tasks.manage_all` для
  `scope=all`; деградация помечается `scope_downgraded` + `notice`.
- **Верификация**: B–G — `sd_acl_scopeall` PASS; на main артефакт
  `real_run_fin_A.json` содержит утечку. Unit-матрица:
  `tests/test_ai_tasks_acl.py` (9 тестов).

## P8. Неоднозначные запросы — открытый класс

- «Почему у меня нет доступа к задачам?» — аналитический запрос; модель
  легитимно диагностирует через `office.tasks.*`+`kb.articles.search`
  (3–4 раунда). Корректно, но дорого — direct-read не применим по смыслу.
- **Класс**: LLM (стоимость аналитических запросов). Кандидат для A11 —
  intent «diagnostic» с ограничением раундов.

## P9. Compact tool specs ухудшают routing и полноту аргументов — schema/prompt (подтверждено точечным экспериментом)

- **Проблема**: `AI_COMPACT_SPECS_ENABLED` (включён по умолчанию внутри
  `AI_PROMPT_OPTIMIZATION_ENABLED`) вырезает из описаний инструментов примеры
  запросов и no-args-дубли. Эксперимент `fin_Bnocompact` (5 деградировавших
  сценариев, compact OFF vs ON): **все 5 вернулись в PASS**, в точности
  повторив baseline A — `sd_tasks_01/02` FAIL→PASS (модель снова передаёт
  status-фильтр), `sd_dir_01/02` FAIL→PASS (правильный выбор инструмента),
  `sd_direct_cmp` llm 6→2, `sd_dir_02` llm 4→2.
- **Причина**: примеры запросов в описаниях несли routing/disambiguation-сигнал
  для gemini-3.7-flash; без них модель хуже выбирает инструмент и реже
  заполняет необязательные аргументы.
- **Класс**: tool schema / prompt. Для A11: не вырезать routing-critical
  примеры; компактизировать только структурный шум (JSON-схемы, no-args),
  либо перенести примеры в system-промпт один раз на группу.
- **Решение для rollout A9**: при включении `AI_PROMPT_OPTIMIZATION_ENABLED=1`
  обязательно `AI_COMPACT_SPECS_ENABLED=0`, пока P9 не исправлен.

## Замечание по метрике

`required_facts` ловит эхо промпта: на `sd_files_01` строка
«bench-doc-007» найдена в ответе-отказе модели (она цитировала запрос).
Для A11 — проверка фактов только по данным трасс инструментов
(result_*), а не по тексту ответа.
