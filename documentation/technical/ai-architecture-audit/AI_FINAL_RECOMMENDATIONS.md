# Итоговые рекомендации для владельца проекта

Дата: 2026-11-23 · Аудит: код + 189 пройденных тестов + изолированный эксперимент поиска + проверка open-source по первоисточникам.

## Одной фразой

Архитектура ИИ зрелая и безопасная по контуру прав (100 инструментов, draft-confirm, серверная идентичность); главные слабости — **качество поиска по базе знаний**, **отсутствие таймаутов на зависшие вызовы** и **неизолированный недоверенный контент в промпте**. Скачок качества дают не агент-фреймворки, а починка FTS + гибридный поиск (fastembed+pgvector+реранкер) + локальный OCR + eval-дисциплина.

## Оценка по областям (1–5)

| Область | Оценка | Комментарий |
|---|---|---|
| Безопасность прав и мутаций | 5/5 | 3-слойная проверка, атомарные карточки, идемпотентность — эталонно |
| Оркестрация/инструменты | 4/5 | JSON-протокол, параллельные вызовы, группы; −1 за отсутствие таймаутов |
| RAG/поиск | 2/5 | Доказанный семантический разрыв, мёртвый GIN-индекс, ACL после limit |
| Память | 4/5 | Сильнее Mem0 (evidence+CAS); −1 за лимит кандидатов и отсутствие retention |
| Документы | 3/5 | Широкое покрытие форматов; −2 за потерю сканов >3 стр. и XLSX-дрейф колонок |
| Наблюдаемость | 3/5 | Runs/traces есть; нет request_id, per-call usage, run-detail |
| Тестирование | 4/5 | ~189 AI-тестов зелёные; −1 за отсутствие eval-регрессии в CI |

## Топ-5 проблем (из AI_GAPS_AND_PROBLEMS.md)

1. **P0** Зависший инструмент убивает поток воркера навсегда: нет таймаутов на run/tool (pyodbc/LDAP/сеть), watchdog выключен. 4 зависания = мёртвый ИИ.
2. **P0** Промпт-инъекция: текст вложений, KB и писем попадает в промпт без маркировки недоверенности; последний рубеж — глаза пользователя на карточке.
3. **P1** Поиск KB: запрос не использует GIN-индекс (concat_ws ≠ `||`), конфиг `'simple'` без русского стемминга, строгий AND роняет разговорные запросы (измерено: Hit@1 67%).
4. **P1** ACL-фильтр KB применён после SQL LIMIT → пользователь видит 0 результатов при существующих доступных статьях.
5. **P1** PII и контент уходят во внешний RouterAI без redaction-слоя (есть только у mail-фичи).

## Что НЕ нужно

- **Langfuse** — 4 новых сервиса; свои логи дешевле доработать. **Mem0** — своя память строже. **FastMCP** — свой реестр богаче, внешних MCP-потребителей нет. **LangGraph/DSPy/NeMo/Outlines/LLMLingua/GPTCache/Unstructured/pg_textsearch** — решают несуществующие у нас проблемы или заменяют работающие части.
- **Отложить**: Docling (пилот при реальном потоке сложных сканов), LiteLLM (один провайдер), Phoenix/OTel, Ragas, ParadeDB, vLLM, Instructor.

## Что уже хорошо — не трогать

3-слойная модель прав с повтором при execute · draft-карточки для всех мутаций с атомарным claim · идемпотентная отправка писем · серверная идентичность `me.*` · память с evidence-цитатами и CAS · ai_sandbox (rootless, выключен) · единый `shared/llm` шлюз с ретраями/DNS-fallback · дедуп очереди и лимиты · параллельное исполнение независимых tool-вызовов · ~189 зелёных тестов.

## Ближайшие действия (порядок)

1. A1+A2+A3 из роадмапа — неделя, без новых зависимостей, закрывает все P0 и половину P1.
2. Замерить recall после A2 на расширенном наборе (~30 запросов).
3. Решение по гибридному поиску (B1) — по замеру.
4. B2+B3 — OCR и eval-дисциплина.
5. C-изменения — только по появлению триггеров.
