# Итоговые рекомендации для владельца проекта

Дата: 2026-11-23 · Аудит: код + 191 пройденный тест + изолированный эксперимент поиска + проверка open-source по первоисточникам.

## Одной фразой

Архитектура ИИ зрелая: 100 инструментов, draft-confirm для всех мутаций, серверная идентичность — по проверенным путям нарушений модели прав не найдено (сквозной pentest не проводился). Главные слабости — **качество поиска по базе знаний**, **отсутствие таймаутов на зависшие вызовы** и **неизолированный недоверенный контент в промпте**. Скачок качества ожидают не агент-фреймворки, а починка FTS + гибридный поиск (fastembed+pgvector+реранкер) + локальный OCR + eval-дисциплина.

## Оценка по областям (1–5)

| Область | Оценка | Комментарий |
|---|---|---|
| Безопасность прав и мутаций | 5/5 | 3-слойная проверка, атомарные карточки, идемпотентность; нарушений по проверенным путям не найдено |
| Оркестрация/инструменты | 4/5 | JSON-протокол, параллельные вызовы, группы; −1 за отсутствие таймаутов |
| RAG/поиск | 2/5 | Семантический разрыв (код+эксперимент на fallback), расхождение запрос/индекс, ACL после limit |
| Память | 4/5 | Контракт строже Mem0 по возможностям (evidence+CAS; совместный бенчмарк не гонялся); −1 за лимит кандидатов и отсутствие retention |
| Документы | 3/5 | Широкое покрытие форматов; −2 за потерю сканов >3 стр. и XLSX-дрейф колонок |
| Наблюдаемость | 3/5 | Runs/traces есть; нет request_id, per-call usage, run-detail |
| Тестирование | 4/5 | 191 AI-тест зелёный; −1 за отсутствие eval-регрессии в CI |

## Топ-5 проблем (из AI_GAPS_AND_PROBLEMS.md)

1. **P0** Нет таймаутов на run и tool-вызовы (pyodbc/LDAP/сеть/subprocess), watchdog выключен — зависший вызов держит поток воркера до возврата; 4 одновременных зависания оставляют ИИ без свободных потоков. Риск доказан кодом; фактическая остановка на проде не воспроизводилась. Важно: deadline/`wait_for` поток не освобождают — нужны таймауты на уровне драйверов.
2. **P0** Поверхность prompt-injection подтверждена кодом: текст вложений, KB и писем попадает в промпт без маркировки недоверенности; успешный эксплойт end-to-end не воспроизводился, рубеж защиты — ручное подтверждение карточки.
3. **P1** Поиск KB: выражение запроса структурно не совпадает с GIN-индексом (`concat_ws` ≠ `||`; план на проде не проверен EXPLAIN), конфиг `'simple'` без русского стемминга, строгий AND. На Python-fallback измерено: Hit@1 12/17, промахи на разговорных словах/опечатках, ложные срабатывания 3/4.
4. **P1** ACL-фильтр KB применён после SQL LIMIT → пользователь может видеть 0 результатов при существующих доступных статьях.
5. **P1** PII и контент уходят во внешний RouterAI без redaction-слоя (есть только у mail-фичи).

## Что НЕ нужно

- **Langfuse** — 4 новых сервиса; свои логи дешевле доработать. **Mem0** — своя память строже. **FastMCP** — свой реестр богаче, внешних MCP-потребителей нет. **LangGraph/DSPy/NeMo/Outlines/LLMLingua/GPTCache/Unstructured/pg_textsearch** — решают несуществующие у нас проблемы или заменяют работающие части.
- **Отложить**: Docling (пилот при реальном потоке сложных сканов), LiteLLM (один провайдер), Phoenix/OTel, Ragas, ParadeDB, vLLM, Instructor.

## Что уже хорошо — не трогать

3-слойная модель прав с повтором при execute · draft-карточки для всех мутаций с атомарным claim · идемпотентная отправка писем · серверная идентичность `me.*` · память с evidence-цитатами и CAS · ai_sandbox (rootless, выключен) · единый `shared/llm` шлюз с ретраями/DNS-fallback · дедуп очереди и лимиты · параллельное исполнение независимых tool-вызовов · 191 зелёный тест.

## Ближайшие действия (порядок)

1. A1+A2+A3 из роадмапа — неделя, без новых зависимостей, закрывает все P0 и половину P1.
2. Замерить recall после A2 на расширенном наборе (~30 запросов).
3. Решение по гибридному поиску (B1) — по замеру.
4. B2+B3 — OCR и eval-дисциплина.
5. C-изменения — только по появлению триггеров.
