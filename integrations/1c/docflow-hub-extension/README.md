# Архив: серверный переходник для 1С Документооборота

Этот переходник больше не входит в активную архитектуру `/docflow`: штатный контур использует `DMService` и не требует изменения конфигурации 1С. Каталог временно сохранён только как исторический rollback-артефакт на контрольный период; не подключайте его к production.

Расширение содержит общий модуль `HUBITДокументооборотСервер` со свойствами:

- `Сервер` — включено;
- `Внешнее соединение` — включено;
- `Клиент (управляемое приложение)` — выключено;
- `Глобальный` — выключено;
- `Привилегированный` — выключено.

Исходник: [Module.bsl](src/CommonModules/HUBITДокументооборотСервер/Module.bsl).

Публичный контракт:

```bsl
ЗаписатьСогласование(Задача, РезультатСогласования) Экспорт
```

`Задача` может быть объектом или ссылкой `ЗадачаИсполнителя`. Внешние изменения объекта игнорируются: модуль извлекает ссылку и повторно читает задание из базы. `РезультатСогласования` должен быть типизированным значением `Перечисления.РезультатыСогласования.Согласовано` из той же COM-сессии.

Модуль проверяет завершённость, тип процесса, текущего исполнителя и активные подзадачи, блокирует процесс, повторно читает состояние и выполняет штатный вызов:

```bsl
РаботаСБизнесПроцессами.ЗаписатьПроцесс(
    ПроцессОбъект,
    "ЗаписьСОбработкойВыполненияЗадачи"
);
```

Готовый изменённый объект бизнес-процесса намеренно не принимается: его привилегированная запись позволила бы внешнему клиенту изменить произвольные поля процесса в обход прав 1С.

Сейчас контракт поддерживает только обычное `Согласовано`. Для замечаний, отклонения и ЭП нужны отдельные проверенные методы, сохраняющие визу и комментарий штатным способом.

Файл `.cfe` необходимо собрать Конфигуратором против фактической версии базы `docflow`, проверить синтаксис модуля и сначала установить в тестовую копию базы.
