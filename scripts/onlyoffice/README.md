# Оформление ONLYOFFICE как HUB-IT

Состояние на 2026-11-03: оформление применено на `10.103.0.11` без рестарта. Проверены 38 файлов
в контейнере и 32 файла резервной копии; напрямую и через `https://hubit.zsgp.ru/onlyoffice`
прошли по 35 проверок HTTP (обычные/gzip-ресурсы, лицензия, содержимое архива). Healthcheck — `true`,
MainPID и ID контейнера не изменились. Сохранение оформления настроено: systemd распознаёт `ExecStartPost`
из `/etc/systemd/system/onlyoffice.service.d/50-hubit-branding.conf`, `NeedDaemonReload=no`.
После отдельного согласия выполнен `daemon-reload` без рестарта. Неподдерживаемый Podman 4.9.3 файл
в `onlyoffice.container.d` сохранён как `.conf.disabled`. Повторный `apply` подтвердил контрольные суммы.
Рестарт и экспериментальное пересоздание production-контейнера не выполнялись.

Редакция оформления v2: **HUB-IT**, прописные буквы, Segoe UI Semibold из стека шрифтов портала.
Контуры букв сохранены в `wordmark.json`: серверу и браузеру не требуется устанавливать шрифт.
Шапка — прежний холст 85×20, высота букв 11 px вместо крупного Arial 18 px; серый цвет `#444`
взят из исходного `dark-logo_s.svg`. Варианты для тёмного фона сохраняют белый цвет.
Namespace кэша v2: `1bf8232ea81dfcfb3947d2a75de71618`. Для получения новой версии обновить страницу портала
и заново открыть редактор: уже загруженный `DocsAPI` может хранить предыдущий namespace в памяти вкладки.

`brand_ui.py` поддерживает только проверенный пакет **10.0.0-169**, исходные файлы которого перечислены в
`original-sha256.json`. Это изменение открытых файлов интерфейса по условиям поставляемой AGPL, а не
включение платного White Label API. Проверки лицензии, JWT, документы и механизм редактирования не меняются.

Изменяются шапка (светлая/тёмная), «О программе», заголовки редакторов документов, таблиц, презентаций,
PDF и схем. В «О программе» добавлена видимая отметка о модификации, авторство, ссылка на лицензию
и архив исходных файлов изменений. Исходные copyright/лицензионные комментарии остаются.

Скрипт меняет namespace кэша в `api.js`, который Nginx уже отдаёт с `no-store`. Остальные ресурсы
кэшируются на год; новый namespace загружает оформление без очистки данных браузера. Сжатые `.gz`
пересоздаются вместе с исходниками. Запущенные процессы редактора и открытые документы не перезапускаются.

## Локальная подготовка

Исходные файлы забираются read-only HTTP-запросами с текущего Document Server в отдельный каталог,
не в frontend `dist`. Полный `LICENSE.txt` для применения берётся из самого контейнера.

```powershell
python scripts/onlyoffice/brand_ui.py stage --source <asset-copy> --destination <staged-copy> --license-file <LICENSE.txt>
```

Проверить `node --check` для изменённых JS, `.gz` на соответствие несжатому файлу, SVG в обеих темах,
заголовки и настоящую форму «О программе» в изолированном браузерном предпросмотре. Проверка предпросмотра
не подтверждает совместное редактирование/сохранение реального документа.

## Применение на TMN-SRV-AI-01

Только при явном разрешении пользователя на этот сервер и это оформление. Перед применением сверить
версию, образ/контейнер, действующий Quadlet, MainPID, доступность `/healthcheck`, свободное место и
отсутствие посторонних изменений целевых файлов. Секреты не передавать аргументами команд.

Разместить `brand_ui.py`, `original-sha256.json` и `wordmark.json` в `/srv/onlyoffice/branding/`, затем:

```sh
python3 /srv/onlyoffice/branding/brand_ui.py apply --container onlyoffice --state /srv/onlyoffice/branding
```

До первой записи скрипт проверяет контрольные суммы всех исходных файлов и их gzip-вариантов. Резервная
копия 32 заменяемых файлов и `receipt.json` находятся в `/srv/onlyoffice/branding/backup/10.0.0-169/`.
Публикация выполняется атомарной заменой каждого файла, API с новым namespace меняется последним.
Перед обновлением уже установленного оформления проверяются все его файлы и сохраняется предыдущая редакция
в `/srv/onlyoffice/branding/releases/<previous-cache-tag>/`, включая предыдущий сценарий применения.
Исходники для новой редакции берутся из проверенной резервной копии оригинала, без накопления замен.
При ошибке записи/проверки контрольных сумм восстанавливается прежнее оформление, при первой установке — оригинал.
Новые файлы сведений об авторстве
при откате сохраняются. Повторный `apply` проверяет все 38 опубликованных файлов, включая `.gz`.

Для сохранения оформления при штатном пересоздании Quadlet-контейнера установлен hook существующего юнита.
Подключение согласовано отдельно. Podman 4.9.3 не подхватывает
`onlyoffice.container.d`, поэтому нужен штатный systemd drop-in:
`/etc/systemd/system/onlyoffice.service.d/50-hubit-branding.conf`:

```ini
[Service]
ExecStartPost=-/usr/bin/python3 /srv/onlyoffice/branding/brand_ui.py apply --container onlyoffice --state /srv/onlyoffice/branding
```

Предыдущий неработающий файл в `onlyoffice.container.d` сохранён как `.conf.disabled`.
После создания нового drop-in — `systemctl daemon-reload`, **без рестарта**. Проверить `ExecStartPost` и
`DropInPaths` в `systemctl show onlyoffice.service`, неизменность MainPID/ID контейнера, healthcheck и отдачу файлов напрямую
и через `/onlyoffice/` портала. Сами документы не используются для тестовых записей.

Минус перед командой означает: ошибка оформления не должна остановить Document Server. Новая версия
или неизвестные файлы не изменяются; при обновлении нужна новая read-only проверка, обновлённый manifest
и отдельное согласование релиза. Образ остаётся официальным `onlyoffice/documentserver`.

## Откат оформления

Только по разрешению на откат. Сначала отключить повторное применение, затем восстановить оригиналы:

```sh
mv /etc/systemd/system/onlyoffice.service.d/50-hubit-branding.conf /etc/systemd/system/onlyoffice.service.d/50-hubit-branding.conf.disabled
systemctl daemon-reload
python3 /srv/onlyoffice/branding/brand_ui.py restore --container onlyoffice --state /srv/onlyoffice/branding
```

Проверить SHA-256 по `receipt.json`, `/healthcheck`, неизменность PID/ID контейнера и интерфейс при новом
открытии редактора. Документы, данные и лицензии не удаляются; уже закэшированное оформление в открытой
вкладке остаётся до её закрытия.
