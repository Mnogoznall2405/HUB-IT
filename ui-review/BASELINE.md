# HUB Desktop — исходное состояние

**Срез:** 20.11.2026, `04fddf24` и локальные изменения рабочего дерева, сборка `Release` (версия проекта `0.1.51`). Это не снимок опубликованной версии. Windows Server 2022, RDP, дисплей 1920×1080, рабочая область 1920×1040, DPI окна 96 (100%). Содержимое чатов и портала на снимках — вымышленные данные.

## Что реально запускается

- Точка входа: [`App.xaml`](../desktop/Hub.Desktop/App.xaml) → [`App.OnStartup`](../desktop/Hub.Desktop/App.xaml.cs). По обычному пути создаётся [`MainWindow`](../desktop/Hub.Desktop/MainWindow.xaml) с WebView2. По `--native` или из пункта трея открывается [`HubWindow`](../desktop/Hub.Desktop/Native/Views/HubWindow.xaml); `--route /chat` выбирает раздел чата после готовности сессии. В релизе штатный клиент настроен на рабочий origin; на этой машине для аудита штатный `App.OnStartup` не запускался: он регистрирует интеграцию оболочки Windows, а обычная конфигурация может открыть рабочий портал.
- Нативный `HubWindow` — отдельное WPF-окно со входом, навигацией, панелью уведомлений и шаблонами для 28 разделов. [`HubShellViewModel`](../desktop/Hub.Desktop/Native/ViewModels/HubShellViewModel.cs) выбирает раздел; [`ChatView`](../desktop/Hub.Desktop/Native/Views/ChatView.xaml) содержит список, ленту, ввод и панели. [`ChatViewModel`](../desktop/Hub.Desktop/Native/ViewModels/ChatViewModel.cs) управляет состояниями, списками, черновиком и запросами; [`ChatView.xaml.cs`](../desktop/Hub.Desktop/Native/Views/ChatView.xaml.cs) — фокусом, горячими клавишами, прокруткой и диалогами файлов. `HubApiClient` использует отдельную нативную bearer-сессию, `HubChatRealtimeClient` — realtime. Чат WebView2/React существует отдельно. Изменения для нативного чата не следует переносить в веб-клиент автоматически.
- Нативное оформление: [`HubTheme.xaml`](../desktop/Hub.Desktop/Native/Themes/HubTheme.xaml), [`HubColorsDark.xaml`](../desktop/Hub.Desktop/Native/Themes/HubColorsDark.xaml), [`HubColorsLight.xaml`](../desktop/Hub.Desktop/Native/Themes/HubColorsLight.xaml), векторные иконки и кисти `DynamicResource`. Лента использует WPF `ListBox` с `VirtualizingStackPanel` в режиме Recycling; подтверждение пользы на большой нагрузке требует замеров.
- Документация `desktop/README.md` и `REPOSITORY_MAP.md` описывает прежде всего оболочку WebView2. На этом срезе исходники **и запущенное демо-окно** подтверждают отдельный нативный путь. Остальные XAML-окна — настройки Desktop, загрузки, диагностика, «О программе», отдельное окно портала/письма и уведомление Windows — перечислены в исходниках, но не открывались в настоящем пользовательском сеансе.

## Эталон Telegram Desktop

- [Официальный preview из `telegramdesktop/tdesktop`](screenshots/reference/telegram-desktop-official-preview.png) · 1892×1308, [источник](https://github.com/telegramdesktop/tdesktop/blob/dev/docs/assets/preview.png). Наблюдения: поиск и список слева; активная строка занимает ширину списка, аватар и имя первичны, время и счётчик справа; у истории заметны заголовок, сообщения и постоянная нижняя строка ввода. Размер окна, версия, ОС изображения и DPI не указаны; точный перенос размеров неприемлем.
- [Пример ночной темы](screenshots/reference/telegram-desktop-2017-night-theme.jpg) · 1280×795, [официальная публикация 2017 года](https://telegram.org/blog/desktop-1-0). Автор темы указан в публикации; это исторический пример, не стандартная палитра текущего клиента. На нём видно положение времени у сообщения, читаемый основной текст и разницу собственного/входящего пузыря без привязки к цветам HUB.
- Официальные [сочетания](https://github.com/telegramdesktop/tdesktop/wiki/Keyboard-Shortcuts) и [их текущая реализация](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/core/shortcuts.cpp) служат ориентиром по клавишам. Локальный экземпляр Telegram Desktop не обнаружен; авторизованный клиент в этом цикле не запускался. Анимация, пороги переключения панелей, реальные границы окна, контекстные меню и настройки актуального Telegram для Windows не измерены.
- Отличия HUB, которые надо сохранить: корпоративная навигация, чат задач, чат поддержки, ассистенты, роли и модерация групп. По эталону оцениваем ясность и поведение, а не переносим тему, иконки или настройки буквально.

### Как воспроизвести без рабочего портала

1. Для широкого набора кадров запустить из корня `tools\dotnet-sdk-8\dotnet.exe test desktop\Hub.Desktop.Tests\Hub.Desktop.Tests.csproj -c Release --artifacts-path <новый-каталог-вне-репозитория> --filter "FullyQualifiedName~NativeScreenshots"`. Не использовать стандартный путь, если в `desktop/screenshots/` лежат чужие снимки: генератор пишет поверх одноимённых PNG.
2. Для интерактивной проверки загрузить реальное `HubWindow` с `FakeHubApiClient` и хранилищем черновика в памяти по образцу [`NativeScreenshots.cs`](../desktop/Hub.Desktop.Tests/NativeScreenshots.cs). Для этого цикла дополнительный временный STA-стенд загрузил ресурсы из `App.xaml` без `OnStartup` и задал тестовому API loopback. `screenshots/before/windows/live-*.png` и `screenshots/defects/` — захват окна `CopyFromScreen`; `wpf-layout-*` и `before/wpf-render/` — WPF `RenderTargetBitmap`. Скриншоты не заменяют тест системного ввода и реального backend.

### Сопоставление «до / после»

Сохранять оригинал «до», а не перезаписывать его. Указывать ID задачи, тему, точный размер окна, DPI, данные/состояние, способ захвата и версию. При сравнении в `after/` использовать те же условия; эталон с неизвестным DPI сравнивать только качественно. Не добавлять снимки реальных рабочих переписок и секретов.
