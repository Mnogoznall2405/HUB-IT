# Цикл 03 — шапка чата, «Заметки», поиск и панель ввода

**8 новых задач, из них одна блокирует два штатных действия панели ввода.** Приёмка UI-001–UI-008 в этом цикле не пересматривалась: 0 принято, 0 возвращено из ранее открытых задач.

## Покрытие

Полный проход для видимой верхней и нижней панелей нативного чата WPF, не всей программы. Проверены два пользовательских кропа, свежий Release на демоданных, ресурсы `HubTheme.xaml` и шаблоны `ChatView.xaml`, локальные кадры Telegram и [официальный preview](../screenshots/reference/telegram-desktop-official-preview.png). В тёмном режиме поставили 1024×600 и 1280×720, открыли «Заметки» и личный чат из состояния без выбора, проверили поле пустое и с черновиком, вызвали поиск из шапки.

| Домен | Результат |
| --- | --- |
| Доступность | Проверены доступность действий, попадание в цель, фокус и доступное имя; физические клавиши и диктор не проверены. |
| Компоновка | Сверены шапка, поиск, разделение истории и панели ввода, позиции левых и правых действий. |
| Тексты | `Not reviewed` — нет `better-writing`; отмечено только доказанное расхождение смысла состояния и действия. |
| Типографика | `Not reviewed` — нет `better-typography`; длинное название уже в UI-005. |
| Цвет | `Not reviewed` — нет `better-colors`; существующий дефект контраста остаётся в UI-001. |
| Визуальная полировка | Сверены форма и заливки, семейство иконок, отдельный вид «Заметок»; движение не проверено. |

## Что не занесено повторно

| Кандидат | Решение |
| --- | --- |
| Длинное имя, светлая выбранная строка, малая ширина карточки | Уже UI-005, UI-001 и UI-002; не заводить дубликаты. |
| Заголовок по центру, круглая отправка и эмодзи в пунктах меню сообщений | В текущей сборке заголовок слева и кнопка отправки плоская. Разметка меню уже переведена на векторные иконки; каждый пункт отдельно не перепроверен. |
| Убрать навигацию портала, копировать название «Избранное» и точные размеры Telegram | Это собственные функции HUB; паритет поведения и иерархии важнее копии. Нет совпадающей по DPI пары окон актуальной Windows-версии. |
| Признать фон обоев причиной некликабельности | `InputHitTest` поля проходит, целевые кнопки отключены; раздельные уведомления модели возвращают доступность без изменения слоёв. |

## Проверка

- `tools/dotnet-sdk-8/dotnet.exe build desktop/Hub.Desktop.Tests/Hub.Desktop.Tests.csproj -c Release --artifacts-path <temp>` — 0 ошибок/предупреждений. Тестовый набор на этом заходе не запускался.
- В STA-стенде `HubWindow` + `FakeHubApiClient`, 96 DPI: в двух чатах × двух размерах попадание в поле подтверждено, `Keyboard.Focus` → `ComposerInput`. У скрепки `CanAttach=True` при `IsEnabled=False`, у эмодзи `CanExecute=True` при `IsEnabled=False`. После точечного `PropertyChanged(CanAttach)` включилась скрепка, после отдельного `RaiseCanExecuteChanged` включились эмодзи; UI Automation открыла панель. Это подтверждает пропущенное обновление на переходе из состояния без выбранного чата.
- Вызов поиска через UI Automation → открыт, фокус остался в `ComposerInput`. Пустое поле → `Send.IsEnabled=False`, с текстом → `True`, отдельных кнопки и команды записи в этом элементе нет. Физический клик, запись микрофона, реальная отправка и 125%/150% не проверены.
- У Telegram сверены [официальная справка Saved Messages](https://telegram.org/blog/new-saved-messages-and-9-more/) и [исходник шапки](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/history/view/history_view_top_bar_widget.cpp): для переписки с собой используется отдельное название, кнопка информации зависит от режима компоновки. Локальный запущенный Telegram не проверялся.
